# Dev/test tooling for the Lambda suites (not shipped to any function).
# Install alongside lambdas/requirements.txt to run lint + tests + coverage:
#   pip install -r lambdas/requirements.txt -r lambdas/requirements-dev.txt
#   pip install -r lambdas/table-builder-infer-schema/requirements.txt   # polars: infer-schema,
#                                                                       # cpcommon.type_mapping +
#                                                                       # data-quality inspect-source
#   pip install -r lambdas/results-conversion-convert/requirements.txt   # xlsxwriter: the
#                                                                       # converter's Excel writer
#
# THE SECOND AND THIRD LINES ARE NOT OPTIONAL, and CI cannot tell you so: the lambdas job runs
# no pytest, so the local suite is the only gate this repo has, and a session missing either
# package fails at collection with an import error that looks like a broken checkout.
# ruff is BOUNDED TO A MINOR, not left open. This repo has no ruff config, so it lints on
# ruff's DEFAULT rule set — and 0.16.0 widened that default from 59 rules to 413, turning a
# green main red overnight with 500 findings in files nobody had touched. An unpinned linter
# means any release can do that again, to every open PR at once. The upper bound makes the
# next widening an explicit, reviewable bump instead of a surprise.
#
# If the default set is ever not what we want, the fix is a [tool.ruff.lint] select in a
# config file — then the rule set is ours and the version bound matters less.
ruff>=0.16,<0.17
pytest>=8
pytest-cov>=5

# mypy is BOUNDED TO A MINOR for the reason stated above ruff: an unpinned checker can
# widen what it enforces in a patch release and redden every open PR at once. It runs
# REPORT-ONLY over the shared layers today (SPEC-153 FR-009); the rule set is selected
# explicitly in pyproject.toml rather than inherited, and the ratchet path is recorded there.
mypy>=2.3,<2.4

# boto3 is DELIBERATELY UNPINNED, and it is the one dependency here that should be.
#
# ruff and mypy are bounded above because a widened default rule set reddens every open PR at
# once and says nothing about this code. boto3 is the opposite case: it is the SUBJECT of an
# assertion, not the instrument. `test_api_module.py` presigns a URL with a real client and
# compares the host against the SPA's `connect-src`, because botocore presigns against the legacy
# global S3 host by default and a URL naming it is blocked by the browser before it is sent —
# every upload failing as a generic network error while downloads, which are navigations, keep
# working. The Lambda runtime supplies boto3 and moves it on its own schedule, so pinning here
# would freeze the guard against a version production has left behind. A release that changes the
# endpoint default SHOULD redden this job; that is the alarm, not the noise.
#
# The cost, stated rather than discovered later: security.yml finds audit targets with
# `find lambdas -name 'requirements*.txt'` and pip-audit BLOCKS, so an advisory against any boto3
# release reddens every open PR — the failure mode the bounds above exist to prevent. Accepted
# because the alternative freezes the assertion, and because a boto3 advisory is worth reading.
#
# Nothing ships it: no requirements file on a DEPLOY PATH declares boto3, because every Lambda
# runtime already provides it. This file has one consumer, ci.yml's lambdas job.
boto3

# PyYAML, for the two workflow guards in test_ci_scope.py. They read `ci.yml`'s scope pattern
# list and every step condition in `security.yml`'s scanner job — both of which stopped being
# structural YAML guarantees and became strings, which is what made them need a guard at all.
# test_config_workflows.py reads it too, to pair each path-filtered workflow's `paths:` lists
# with the files its steps run.
#
# A real parser rather than the anchored regexes test_security_gates.py uses next door. Those
# read fixed keys; these walk a step LIST and pair each step with its `if:`, and a regex that
# silently pairs the wrong two passes while asserting nothing. The guards carry their own
# "the parse did not go trivial" controls either way.
#
# Bounded to a major, not a minor: PyYAML's rule set is a file format rather than a lint
# opinion, so it does not widen what it enforces the way ruff and mypy can. The cost noted
# above boto3 applies here too — pip-audit BLOCKS and reads this file — and is accepted for a
# dependency this stable.
#
# Absent from CI is how this was found: it is ambient on a developer machine, so the suite ran
# green locally and the `lambdas` job failed at collection.
PyYAML>=6,<7
