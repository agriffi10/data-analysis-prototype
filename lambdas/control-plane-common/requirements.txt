# External dependencies for the shared control-plane package (cpcommon).
#
# PyJWT[crypto] — the API verifies the caller's bearer against the provider's JWKS
# (cpcommon.auth), and it is the ONLY caller left: the control planes read the trusted actor
# out of the message instead, so no verb decodes a token any more. The dependency stays
# because the API resolves cpcommon. It is declared HERE, once; the domain packages
# (tbcommon / tscommon / dqcommon) do not declare it. The image installs this file into the
# fleet's single site-packages, so nothing bundles it per function.
PyJWT[crypto]>=2.8,<3

# polars is DELIBERATELY NOT HERE, even though cpcommon/type_mapping.py imports it.
#
# The original reason was size: this was attached to every control-plane verb, and polars is
# ~100 MB unzipped against Lambda's 250 MB per-function ceiling. That reason is GONE — the
# image installs every requirements file into one site-packages, so polars ships to all 86
# functions whether or not this line exists.
#
# What the omission still does is say WHO is meant to read Parquet footers:
# table-builder-infer-schema and data-quality-inspect-source declare it, and a verb that
# imports type_mapping without declaring polars is now a successful import rather than a
# cold-start error, which is a quieter failure than the one this comment used to prevent.
#
# type_mapping.py is safe to live in this layer because cpcommon/__init__.py imports no
# submodules, so the polars import only runs for a verb that explicitly imports
# type_mapping — and those are exactly the two carrying a polars layer. That module's
# docstring has the full constraint, including the __init__ rule.

# log-foundry — structured logging for the control-plane verbs (SPEC-127).
#
# PINNED EXACTLY, not >=. Every control-plane verb resolves this package — and one image carries it
# to the whole fleet — so an unattended minor bump would change the behaviour of all of them at
# once, at cold start, with no PR to review it.
#
# The CORE package, deliberately NOT the [aws] extra. The extra exists only to pull boto3;
# SQSSink imports it lazily inside __init__, and the Lambda runtime already provides boto3 —
# installing the extra would put a second copy of boto3/botocore on every control-plane verb's
# 250 MB ceiling to gain nothing. The core install declares zero runtime dependencies: every
# Requires-Dist is behind an extra, re-confirmed on this pin.
#
# WHAT THE VERSION BUYS, as opposed to what it fixed on the way here. The floors that justified
# Every floor that justified an earlier pin is gone, because this one clears all of them; what is
# kept below is the set of
# facts that are TRUE OF THE RUNNING LIBRARY and are recorded in no other live file. Deleting one
# of these deletes it from the repo.
#
# 1. `error.stack` keeps the cause's text, clipped at 32 KB, tail-preserving — well above a real
#    traceback. That ceiling is what makes the SPEC-110 tripwire's premise checkable.
# 2. `error.message` and `error.module` exist as their own fields, so filtering an error stops
#    meaning substring-matching the free-text `stack` blob. This is the counterpart to the
#    `error.stack` exemption the register leans on: the exemption accepts a stack that may quote
#    file contents, and these two are why an operator need not read it to find anything.
# 3. An event is safe by construction — every value is coerced and size-bounded once at assembly,
#    so a field whose JSON cannot serialize no longer raises. That is what lets a call site put an
#    arbitrary object in a field.
# 4. `span.end` carries `duration_ms` and `status`, and baggage is backfilled onto BOTH boundary
#    events at close. That pair is why stamping a correlation key as baggage is worth doing: a
#    filter on `fields.request_id` returns the span's narration AND the span.end carrying the
#    duration and outcome — the record actually worth finding — rather than the narration alone.
# 5. A `stamp`/`info` OUTSIDE a span emits SYNCHRONOUSLY on the caller's thread, where one inside a
#    span is buffered until the worker flushes. This is why the orphan path is the one that used to
#    raise into the verb, and it is why decorating a helper that already narrates changes when its
#    existing events are delivered.
# 6. `MultiSink` re-raising when every child fails does not reach this repo: the sink here is
#    SQSSink ALONE (SPEC-127, asserted).
# 7. The non-JSON sinks' datetime storage does not reach it either — mongo/postgres/sqlite/
#    clickhouse are none of them used.
#
# 6 and 7 are stated without a version deliberately. They were introduced before this pin, so
# naming their release would leave a superseded version string in the one block a sweep exists to
# clear; and attributing them to this pin would be false. The disposition holds for every version.
log-foundry==1.0.0
