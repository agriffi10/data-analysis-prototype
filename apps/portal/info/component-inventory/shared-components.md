# Shared components (`apps/portal/src/components/`)

> **Sizes here are named in Tailwind classes, not pixels, and that is deliberate.**
> `index.css` sets a **14px root**, so every rem-named size renders 12.5% under what its
> name suggests — `h-6` is 21px, `h-8` is 28px, `h-11` is 38.5px. Rows that used to state
> px figures were stating them for a 16px root and were wrong by that much.

Part of the component inventory (`INDEX.md`, beside this file, is the router).
Public surface only — the code is the source of truth; verify signatures before relying on them.

| `Header` | `components/Header.tsx` | App header (sign-in/out, identity). Below `tablet` a hamburger (`h-11`, `aria-controls`) opens `AppNavDrawer`; `PrimaryNav` is `hidden tablet:flex` (SPEC-095). |
| `CollapsibleRail` | `components/CollapsibleRail.tsx` | Shared 248px left-rail chrome (`{ariaLabel, title?, widthClass?, children}` — `widthClass` narrows it per host, e.g. the Query rail's 220px tablet band, SPEC-100) for the Files `Sidebar` + Query `SchemaBrowser`: `hidden … tablet:flex` panel + header collapse control + a reopen handle when collapsed; collapse = `display:none` (panel kept mounted so in-rail state + `aria-controls` survive). | `AppNavDrawer` | `components/AppNavDrawer.tsx` | Mobile off-canvas nav (`{open, onClose, id?, contextualRail?, actions?}` — `actions` is a generic slot for chrome controls that live in the header at `tablet` and above and have nowhere to go below it; the drawer may not import `features/`, so `Header` composes them and passes the node down — **currently unfilled**, its one occupant having moved to `UserMenu`): 300px left sheet, five primary links (active via `NavLink`) + page-supplied rail slot; focus trap + scroll lock + Escape/scrim/link dismiss. Its header carries `BrandMark size="sm"` rather than a `Menu` caption: below `desktop` the bar shows the brand SQUARE alone, so this is the only place the app is named on screen. Mounted by `Header` only when `useIsMobile` (SPEC-095). |
| `NavRailProvider` / `useProvideNavRail` / `useNavRailContent` | `components/NavRailProvider.tsx`, `components/navRailContext.ts` | Bridges a page's contextual rail to the Header-owned `AppNavDrawer` (`useProvideNavRail(memoizedNode)` registers; drawer reads via `useNavRailContent`). Wrapped around the shell in `RootLayout` (SPEC-095). |
| `MobileActionBar` | `components/MobileActionBar.tsx` | Fixed-bottom `tablet:hidden` action toolbar (`{children, ariaLabel?}`), safe-area-inset aware, `h-11` targets; consuming page pads its scroll region by the bar height. Shell only (SPEC-095). |
| `Menu` (+ `MenuItem`/`MenuProps`) | `components/Menu.tsx` | Accessible menu primitive: render-prop `trigger` (`{open, toggle, ref, menuId}`) + `role="menu"` popover (arrow roving, Escape/outside-click close + focus return); `items` = action (`icon?`, `tone: default\|danger`, `disabled?`, `disabledReason?`) or separator; `align`/`className`/`menuClassName`. **Prefer `disabledReason` over `disabled`** — `aria-disabled` + `title`, handler dropped, item kept in the roving focus order, exactly as `Button.disabledReason` behaves; opening focus still skips it. Selecting an item **returns focus to the trigger**: the item unmounts with the menu, so releasing focus leaves it on `document.body` and the next Tab restarts at the top of the page. Added when the Data Explorer's toolbar moved into a menu: an item that merely greyed out would have put the reason further from the user than the button it replaced. Extracted from `TableActionsMenu` (SPEC-095); also backs `LandingNavMenu` (SPEC-104) and `ExplorationOptionsMenu`. |
| `SpaceSelect` | `components/SpaceSelect.tsx` | The "which space" `<select>` above a `DestinationPicker`. **Renders nothing for a single space** — a one-option control is the shape the gating rule declines to render. Extracted at its THIRD consumer (`SaveResultsDialog`, `StartQualityCheckDialog`, `CreateTableFromSpaceDialog`), which had already drifted over whether a shared space says so in its option text; `kind` is optional, so each caller keeps the text it shipped. Typed structurally — `components/` may not import `features/`. |
| `LandingNavMenu` | `routes/LandingNavMenu.tsx` | Mobile-only (`tablet:hidden`) hamburger for the landing page's section anchors (`{links}`), composing `Menu`; each link sets `window.location.hash` and closes (SPEC-104). |
| `useRailCollapsed()` | `components/useRailCollapsed.ts` | `localStorage`-backed rail collapse state under one shared key (`RAIL_COLLAPSED_STORAGE_KEY`) so it carries across both rails; `{collapsed, toggle, setCollapsed}`; guarded access → default expanded when storage is unavailable (SPEC-085). |
| `Button` (+ `ButtonVariant`/`ButtonSize`) | `components/Button.tsx` | Design-system button — `variant` primary/default/ghost/danger, `size` sm/md/lg, `forwardRef` (SPEC-028; `lg` added SPEC-029). **`disabledReason` (SPEC-172)** = unavailable AND saying why: renders `aria-disabled` rather than `disabled`, so the control keeps its place in the tab order and the reason is reachable as the accessible DESCRIPTION (`title`) rather than only on hover; the click is swallowed here so a caller cannot forget to guard its handler. Deliberately not rendered inside the button — text in the content becomes part of the accessible NAME, which registry rows and tests query by. Use `disabled` for an in-flight operation: that is not a refusal. |
| `IconButton` | `components/IconButton.tsx` | Ghost icon-only button; `label` → aria-label, `forwardRef` (SPEC-028). **Both sizes clear WCAG 2.2 SC 2.5.8's 24px floor** — `sm` is `h-7`, which clears it by half a pixel, and `md` is `h-8` — which is why reaching for this instead of a hand-rolled `<button>` keeps an icon control out of `src/lib/targetSize.test.ts`'s accepted register. Every `SIZES` map in this directory is pinned there; normalising `sm` down one scale step would cost every call site at once. |
| `Input` | `components/Input.tsx` | Text input with `label` + `error` state, aria wiring, `forwardRef` (SPEC-028). |
| `Badge` | `components/Badge.tsx` | Neutral pill — file/folder type labels, the roster's Owner tag, the connections role pill, the data-quality Sampled tag (SPEC-028; SPEC-186 FR-010 folded three hand-rolled copies into it). |
| `StatusPill` | `components/StatusPill.tsx` | A status as a tinted pill with a dot and a TEXT LABEL — `tone` (`success`/`warning`/`danger`/`neutral`), optional `dot`, `pulse` for a state still moving. The label always carries the meaning, so it has no colour-only mode (SPEC-186 FR-010). Seven sites. |
| `Chip` / `ChipList` | `components/Chip.tsx` | One removable recipient chip and its wrapping list. `h-[24px] w-[24px]` remove target — written absolutely because 24 is WCAG 2.2 SC 2.5.8's threshold, not a spacing step (see the note at the top of this file); a source tripwire pins it. Width bounded for a 63-character username, `removeLabel` supplied whole by the caller (never derived — SPEC-163's registry queries by name). The caller keeps the block's own margin. (SPEC-186 FR-009) |
| `Banner` (+ `BannerVariant`) | `components/Banner.tsx` | Dismissible status banner — success/warning/danger/info, optional `title`/`onDismiss`, and an optional `retry`/`retryLabel` action replacing the hand-rolled "Try again" link-buttons two pages carried (SPEC-028; retry SPEC-155 FR-004). |
| `ErrorBanner` | `components/ErrorBanner.tsx` | `Banner` wrapper that renders `toUserMessage(error)` mapped text for a caught/`ServiceResult` error; defaults to `danger` (SPEC-106). |
| `ErrorBoundary` | `components/ErrorBoundary.tsx` | Class error boundary (the sanctioned non-function-component exception). Catches a render/lifecycle throw and renders a reload fallback with authored copy — never `error.message`. Optional `fallback` replaces the panel. Wraps both lazy routes and `RootLayout`'s `Outlet`; Suspense has no error path, so a chunk-load rejection would otherwise unmount the tree (SPEC-150). |
| `ToastProvider` / `useToast()` | `components/ToastProvider.tsx` / `components/toastContext.ts` | App-level toast host (mounted once in `main.tsx`); `useToast()` → `{push({variant,message,action?}), dismiss()}`. Single-toast semantics; reuses the `Toast` view. Replaces per-page toast state (SPEC-106). |
| `BrandMark` | `components/BrandMark.tsx` | Accent-square upload-arrow icon + wordmark; `size` sm/md, `showWordmark`, `wordmarkClassName` (SPEC-028; used by Header, `AppNavDrawer` and LandingPage). `showWordmark` is whether this mark has words at all; `wordmarkClassName` is whether there is room for them right now — the signed-in header passes `hidden desktop:inline`, because naming three bar controls costs the width the words were using. |
| `PrimaryNav` | `components/PrimaryNav.tsx` | Topbar Files \| Query underline tabs (`NavLink`-driven); rendered by `Header` only when authenticated (SPEC-035); wrapped `hidden tablet:flex` on mobile (SPEC-095). |
| `useBreakpoint()` / `useIsMobile()` | `lib/useBreakpoint.ts` | `matchMedia`-backed viewport tier (`{isMobile, isTablet, isDesktop}`; thresholds 900/1300), `useSyncExternalStore`, SSR-safe. **Mount-gating only** — never styling (that's `tablet:`/`desktop:` variants) (SPEC-095). |
| `Modal` | `components/Modal.tsx` | Centered modal shell (SPEC-026 pattern): scrim + surface card + role/aria + backdrop-dismiss + Escape (`useEscapeKey`); `dismissible` locks it during in-flight actions and **swallows** Escape rather than letting it dismiss the layer beneath (SPEC-155 FR-006); `className` replaces the default `max-w-md`, and an EMPTY string counts as omitted (SPEC-186 FR-007 — `??` does not fall back on `''`, which cost nine dialogs their width); viewport-capped + scroll-in-panel on small screens (SPEC-095). Children supply body + footer. (react-best-practices pass) |
| `ConfirmDialog` | `components/ConfirmDialog.tsx` | Warn-and-confirm dialog over `Modal`: title (+ optional danger icon `tone`), body `children`, optional `irreversible` line, `confirmVariant`, `busy`/`busyLabel`, `confirmDisabled` (gate confirm only — e.g. type-the-name, SPEC-054) with `confirmDisabledReason` swapping the native `disabled` for `aria-disabled` + a reason (SPEC-186 FR-002; `busy` still wins and stays natively disabled), `dismissOnly` (single-button info), focus defaults to Cancel. Used by Clear/CloseTab/DropTable/TabLimit/delete-confirm/overwrite-confirm. (react-best-practices pass) |
| `Drawer` | `components/Drawer.tsx` | Slide-over (SPEC-036): scrim + panel + header (title, `headerAccessory`, close button) + scrollable body + optional `footer`; Desktop = 440px right slide-over; below `tablet` a full-width sheet via `mobileVariant: 'bottom-sheet'`(default)`\|'full-height'` (SPEC-095). Used by history / saved-queries / upload / member drawers. (react-best-practices pass) |
| `PageLayout` | `components/PageLayout.tsx` | Full-width page chrome (title/subtitle/`actions` header over a padded, width-capped content column) — the page's `<main id="main">`. `stackActionsOnMobile?` (default off) stacks the header below `tablet` (SPEC-102). Hosts: Connections, Notifications. |
| `Pager` | `components/Pager.tsx` | Prev / range-label / Next pager (SPEC-038 styling), `nextBusy` "Loading…" state; Prev/Next `h-[38px] tablet:h-9` (full touch height on mobile, SPEC-102). Shared by the query-results table + history drawer. (react-best-practices pass) |
| `LoadingState` | `components/LoadingState.tsx` | Centered `role="status"` "Loading…" indicator (route Suspense fallback + auth gate). (react-best-practices pass) |
| `FolderIcon` / `UploadIcon` / `DocumentIcon` / `CopyIcon` / `CheckIcon` / `PencilIcon` / `DownloadIcon` / `TrashIcon` / `TrashLidIcon` / `FolderRowIcon` / `FileRowIcon` / `PlayIcon` / `SaveIcon` / `EyeIcon` / `DatabaseRowIcon` | `components/icons.tsx` | Shared inline SVG icons (no icon lib); `className` for size/color; `FolderIcon` takes `filled`. | `CopyButton` | `components/CopyButton.tsx` | Icon-only copy-to-clipboard button; `value` + `label` (→ `Copy {label}` aria-label), swaps to a check + polite live-region announce on success. Built on `useCopyToClipboard`. |
| `FormDialog` | `components/FormDialog.tsx` | Name-a-thing dialog over `Modal`, and the deliberate sibling of `ConfirmDialog` (same prop shape). | `RefreshIconButton` | `components/RefreshIconButton.tsx` | The one refresh affordance: `IconButton` + a single spinner glyph, disabled and spinning while `busy`. Replaces three divergent refresh glyphs (SPEC-155 FR-004/FR-006). |
| `SELECT_CLASS` | `components/fieldStyles.ts` | The chrome for a bare `<select>`. There is still no `Select` primitive; it moved down from the Data Explorer at its first consumer outside that feature and is re-exported from its old home, so a second copy cannot start. |

| `Toast` (+ `ToastState`) | `components/Toast.tsx` | Minimal transient toast (success/danger auto-dismiss; `info` persists), accessible live region, fixed bottom-right; optional inline `action` (e.g. "View in Files"; suppresses auto-dismiss). | `BootFailure` | `components/BootFailure.tsx` | What renders instead of the app when the runtime configuration cannot be loaded. Mounted directly by the bootstrap, inside no provider and no router, so it takes no context; names no key, no value and no URL (SPEC-192). |
| `ThemeMenu` | `components/ThemeMenu.tsx` | The theme control — `HEADER_CONTROL` + `Menu`, one instance on the top bar for BOTH auth states, next to notifications. It spent one release as a section of `UserMenu` and came back: an unnamed trigger holding an unrelated set of options is not where a user looks for the theme. Visible word `Theme` at `tablet` and up, `aria-label="Change theme"` at every width. The choices themselves are `THEME_OPTIONS` in `lib/useTheme` (a constant exported from a component file breaks fast refresh). |
| `UserMenu` | `components/UserMenu.tsx` | The account menu behind the kebab beside the username (`{username, onGiveFeedback, onSignOut}`): Give feedback, then Sign out last, each with an icon. Help and the theme are NOT here — both are named controls on the bar, because a menu is a click the user pays for a control they were looking for. **Presentational** — `components/` may not import `features/`, so `Header` (which is exempt) wires both callbacks. The trigger carries its own `aria-label` naming the user, because the avatar is `aria-hidden`, the kebab is decorative and the username is CSS-hidden below `tablet`. |
| `ThemeIcon` | `components/icons.tsx` | Half-filled circle; the theme control's glyph in both presentations (SPEC-210). |
| `KebabIcon` | `components/icons.tsx` | Three stacked dots — the affordance that says a control opens a menu. Filled circles, not a stroked path: at 16px a round-cap stroke renders as a smudge and the three marks stop reading as three. |
| `HEADER_CONTROL` (+ `_ACTIVE`/`_IDLE`/`_LABEL`) | `components/headerControl.ts` | The class strings for a control on the top bar — help, notifications, the theme. One owner rather than three copies that agreed only while all three were icon-only. `h-8 px-1.5` is the same 28×28 box an icon-only control had; `_LABEL` is `hidden tablet:inline`, so a phone loses the word and keeps the button. |
