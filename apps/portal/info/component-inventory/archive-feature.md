# Archive feature (`apps/portal/src/features/archive/`)

Part of the component inventory (`INDEX.md`, beside this file, is the router).
Public surface only — the code is the source of truth; verify signatures before relying on them.

SPEC-172 shipped the whole area at once: both enqueue surfaces, both entry points, both dialogs.
The outcome notifications are produced in Python (`lambdas/archive-notify/`) and are not part of
this surface. The `archive/` folder's read-only behaviour is a FILE-BROWSER concern and lives in
`file-browser-feature.md` (`isWriteLockedPrefix`), not here.

**This feature imports nothing from another feature** (SPEC-172 FR-005 AC5), which is why its
dialogs carry their own name/path helpers rather than reaching into `features/file-browser`.

| Symbol | File | Purpose |
|---|---|---|
| `enqueueArchive(req)` | `archive.service.ts` | One `apiRequest('archive.archive')` carrying `requestId` + `source.{space,items}`, plus `archiveName` when the request's `name` is anything after normalising (the service normalises it again because it is the wire boundary). The envelope's server half — the `mode` literal, the verified actor, the identity block and the FIFO keys — is the API's; the dedup id is the `requestId`, which is **also the archive's permanent identity**, pinned by golden vectors in `lambdas/api/test_fifo_derivations.py`. Refuses over-cap selections locally (200 items / 87 KiB serialised, mirroring `arcommon.config` — a Python test reads both numbers back out of this file) with code `SelectionTooLarge`, before any call. `ServiceResult<void>` (enqueued ≠ archived), never throws. |
| `enqueueRestore(req)` | `archive.service.ts` | The SPEC-170 restore envelope (`space` + `archiveId` in place of `source`; the field sets are per-mode and unknown fields are REJECTED, so a superset would be refused). Sends `{requestId, space, archiveId}` to the API's `archive.restore` route, which derives the `MessageGroupId` — SHA-256 of the **archive root**, `"{kind}/{name}/archive/{archiveId}/"`, so the restores of ONE archive share a group, which orders their starts and does not serialize the runs (`apicommon.fifo`). **Deliberately not `{archiveBucket}/{archiveRoot}` as SPEC-170 FR-001 wrote it**; see `docs/decisions/archive-and-restore/`. |
| `useArchive(space, notify)` | `useArchive.ts` | Dialog + enqueue state for Archive. `open(items)` / `close()` / `submit(name?)` → **`Promise<boolean>`**: the caller clears the selection and invalidates the listing from the RETURN VALUE, because `error` read from the enclosing closure is the value from before the submit. Mints the `requestId` **per submit**. Never wedges: `busy` clears in `finally`, a throw becomes a user-safe error, and a second click in the same tick is dropped by a ref rather than by `busy`. |
| `useRestoreArchive(space, notify)` | `useArchive.ts` | The same for Restore: `openDialog()` / `close()` / `submit(archiveId)` → `Promise<boolean>`. Lowercases and trims the pasted id (S3 keys are case-sensitive, so one archive must have one prefix). The run id and the archive id are always different values. |
| `isArchiveId(value)` | `archiveId.ts` | The client-side UUID-v4 rule, held to the SAME pattern `arcommon.paths` uses. The server is the boundary; this exists so a typo costs a sentence now rather than a notification hours later, and `listArchives` uses it to tell an archive's receipt folder from anything else there. |
| `ArchiveButton({onClick, disabledReason?, disabled?, placement?, label})` | `ArchiveButton.tsx` | The entry point, in the two homes a per-item action has in this file browser: `placement: 'toolbar'` (icon-only on mobile, the word alone at `tablet` and both at `desktop`, like Copy/Move/Delete — `TOOLBAR_ACTION_*`) and `'panel'` (full width, in both details panels). `disabledReason` renders through `Button`'s `aria-disabled` path, so the refusal stays focusable. `label` is the ACCESSIBLE NAME and is queried by the `GATED_SURFACES` walking test. |
| `ArchiveDialog({items, rootPrefix, busy, submitError, onConfirm, onCancel})` | `ArchiveDialog.tsx` | The confirm, on `ConfirmDialog` **because** `FormDialog` has the Enter-to-submit affordance this dialog must not have — which is also why its optional **Name** field sits in no form. Says where the data goes, that a restore puts every file back where it was and overwrites nothing ("move or rename" what is in the way), that a restore takes hours, the 90-day storage charge, and how to find the archive again. `onConfirm(name)` gets the name normalised; a refused one keeps the dialog open with the reason on the field. Focus lands on Cancel, `busy` locks dismissal, and it never says "This can't be undone". |
| `RestoreArchiveButton({onClick, placement?})` | `RestoreArchiveButton.tsx` | The primary-toolbar control. `placement: 'toolbar'` sits at its natural width with the whole label; `'action-bar'` fills the mobile action bar's row and shows just "Restore", keeping "Restore Archived Data" as the accessible name, because the whole label wraps to three lines in a third of a phone's width. The bar is mount-gated rather than CSS-hidden (SPEC-099 FR-005). |
| `RestoreArchiveDialog({space, spaceLabel, busy?, submitError?, onSubmit, onCancel})` | `RestoreArchiveDialog.tsx` | Picks an archive from the space's list (`useArchiveList` + `ArchiveList`), with **Restore by archive id instead** one link away in every state for the archive the list cannot show. List mode focuses the list's heading, never a radio, and Enter does nothing there; id mode focuses the field and Enter submits from it. Nothing is selected at first, and Restore says so rather than being disabled. Names the space the restore lands in (it comes from the route). |
| `listArchives(space)` | `archive.service.ts` | The restore list: every archive with a receipt folder (pages `objects.list`, up to 100 pages), labelled from the space's `index.json` through `readJsonDocument` where it has an entry. The folders are the authority; any failure reading the index is no labels, and only the folder listing failing is a failure. Newest first, unlabelled rows last. `ServiceResult<ArchiveListing[]>`. |
| `useArchiveList(space, enabled)`, `archiveKeys` | `useArchive.ts` | The TanStack Query over `listArchives`: stale at once so every opening re-reads, not refetched on focus so rows cannot reorder under a selection. |
| `ArchiveList({status, listings, selectedId, onSelect, showArchivedBy, onRetry})` | `ArchiveList.tsx` | One native radio per archive — title (name, else what it held, else the id's start), details, and what its last restore did. Only a `restored` row is disabled. Loading, empty and a retryable failure. |
| `normalizeArchiveName(raw)`, `archiveNameRefusal(raw)`, `ARCHIVE_NAME_MAX_CHARS` | `archiveName.ts` | The name rule, held to `arcommon.names` by a Python constants mirror and by `lambdas/archive-common/archive_name_corpus.json`, which both suites run. U+0020 only, by code point. |
| `ARCHIVE_RESERVED_ROOTS`, `archiveRefusal(items, rootPrefix)` | `archiveSelection.ts` | The portal-managed roots that may never be an archive source, mirroring `arcommon.config.RESERVED_SOURCE_ROOTS` — **set equality is asserted by a test**, because a divergence shows up as a request the browser sends and the plane refuses. `archiveRefusal` reproduces all THREE ways one is selected: the folder, anything beneath it, and an ANCESTOR that contains it (selecting the space root). Anchored at the space root, so a user's own `alice/backups/archive/` is archivable. |
| `ArchiveRequest`, `RestoreRequest`, `ArchiveItem`, `ArchiveSpace` | `src/types/archive.types.ts` | The request shapes matching the SPEC-168/170 contracts. A folder's `key` carries its trailing slash — the plane expands a folder by LISTING that prefix. |
