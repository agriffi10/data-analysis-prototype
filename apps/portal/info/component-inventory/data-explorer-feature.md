# Data Explorer feature (`apps/portal/src/features/data-explorer/`)

Part of the component inventory (`INDEX.md`, beside this file, is the router).
Public surface only — the code is the source of truth; verify signatures before relying on them.

Public barrel: `features/data-explorer/index.ts`. Look at a table without writing SQL: a user's
grid gestures are a **description of a query**, and the app renders that description and runs it.

**SPEC-179 mounted the first surfaces** (the `/explore` route, the source picker, the tab strip),
**SPEC-180 replaced its placeholder table with the real grid** (column geometry, a cell cursor with
range selection, the Value panel, and the Record and Text presentations), **SPEC-181 made it
usable** (the per-column menu, filter-by-cell, the expression bar, multi-column ordering, the staged
settings dialog, history and cost) and **SPEC-182 added the two analysis panels** — Calc over the
selection, computed in the browser, and Grouping, which is a real `GROUP BY` — plus the
generated-SQL disclosure. The engine shipped first
(SPEC-178) because it settles the exploration model and the app's only SQL-value interpolation
point.

> Composes `features/catalog/` (the Glue reader, the Athena execution/results layer) and
> `features/saved-queries/` (the `.sql` store, from SPEC-183). It may **not** import
> `features/query/`, and `features/query/` may not import it — enforced by the ESLint layering
> rule (SPEC-176), which this spec is the first to exercise against real files.

### The rule everything else follows

`renderExplorationSql(source, query)` takes the source and the query description **and nothing
else**. Filters, the expression, ordering and grouping render SQL; column visibility, order,
pinning, width, colour and transformers are *presentation* and render nothing, so they cost
nothing and apply instantly. That is structural — a function that cannot reach presentation state
cannot be made to depend on it by a later edit — and `sqlBuilderSweep.test.ts` forbids a second
builder in the feature.

### Model & rendering

| Symbol | File | Purpose |
|---|---|---|
| `renderExplorationSql(source, query)` | `renderExplorationSql.ts` | The ONE SQL builder. `table` → `FROM "db"."tbl"`, `sql` → `FROM (\n<body>\n) AS t` (the newlines are load-bearing — a body ending in a `--` comment would otherwise swallow the closing paren and the alias); filters, expression, ordering and grouping compose identically over either arm. `SELECT *` unless grouping, no trailing semicolon. Throws `ExplorationRenderError` for a description that cannot render — a valueless comparison, a non-numeric numeric value, an invalid or ambiguous grouping, or an ORDER BY Trino would reject. (Trino rejects that last one at ANALYSIS, scanning nothing and billing nothing — what refusing here buys is immediacy, not money: the gesture is refused where the user made it instead of returning an engine error SPEC-106 forbids rendering.) |
| `ExplorationRenderError` | `renderExplorationSql.ts` | The refusal. Its message is **operator text** and names the offending column — SPEC-106 forbids rendering it to a user. |
| `aggregateAlias(aggregate)` | `renderExplorationSql.ts` | The column name an aggregate produces (`COUNT(*)` → `count_all`), and the name an `ORDER BY` may reference. Exported so SPEC-182's panel labels a column with the name the SQL actually emits. |
| `newExploration(source, id?)` / `newExplorationId()` / `emptyExplorationQuery()` / `emptyExplorationPresentation()` / `emptyGrouping()` / `explorationSourceLabel(source)` | `exploration.ts` | The model's constructors — one definition of what "empty" means, so two surfaces cannot disagree about whether `expression` starts `null` or `''`. `emptyGrouping()` is a panel DRAFT: `COUNT(*)` and no columns, which is deliberately **not** grouping mode. |

### Execution & cost

| Symbol | File | Purpose |
|---|---|---|
| `useExploration(exploration \| null, tabId?)` | `useExploration.ts` | Renders, runs and reports: `{sql, queryExecutionId, state, cost, isPending, error}`. A FAILED/CANCELLED execution is surfaced as an `error` of `{code, message: stateChangeReason}` (SPEC-181) — Athena's refusal is not an error anywhere in the plumbing (the poll RESOLVES), and that shape is what `toUserMessage` maps engine text from. A watch that outlived its ceiling arrives as `error` too (`isQueryStillRunning`), and ends `isPending`; `tabId` is the watch key, so switching to a tab that shares the execution looks again (SPEC-234). **The rendered SQL is the cache key**, so an identical description is a cache hit rather than a second bill and toggling a sort back costs nothing. Paging is NOT here — the caller pages the execution id through SPEC-176's `useQueryResults`, whose `NextToken` walk scans no extra bytes. A FAILED/CANCELLED execution is evicted **on the way out** (statement change or unmount), never on observing the failure: evicting while mounted refetches immediately, an unbounded loop against StartQueryExecution (AWS does not bill a FAILED query, but this branch also covers CANCELLED, which IS billed for what it scanned). `gcTime: Infinity` is as load-bearing as `staleTime` — under the 5-minute default the cache promise silently expires and the return trip becomes a second execution. |
| `explorerKeys` | `explorerKeys.ts` | Key factory (`all` / `execution(scope, sql)` / `table(db, t)` / `database(db)` / `sqlSources()`), rooted at `['data-explorer']` — never hand-build keys. The source scope sits IN FRONT of the SQL so the cache can be evicted by what changed: keyed by SQL alone, a table dropped and rebuilt under the same name rendered byte-identical SQL and stayed a cache hit for the session. |
| `explorationSourceScope(source)` | `explorerKeys.ts` | The `[kind, database, table]` triple a source contributes to its key — a **table** source files under its database AND its table, which is what makes a precise eviction possible, a **saved query** under one shared `sql` scope, because its body is arbitrary SQL over any number of databases and this app has no parser. |
| `ExplorationOptionsMenu` | `ExplorationOptionsMenu.tsx` | The menu holding every action — Order and filter, Remove all filters, Filter by this value, Columns, Colours, Transformers, Value, Calc, Grouping, Copy…, Save results to my files, Save as query, Create view…. The bar keeps undo/redo and the view switch: the controls whose current state has to be readable, and which are used repeatedly rather than once per decision. The earlier split (query-changing controls stayed on the bar) was REVERSED on user feedback asking for a shorter bar. `Create view…` sits beside `Save as query` and follows the same `query` flag — creating a Glue view is a Query capability wherever the control lives. Refusals ride `MenuItem.disabledReason`, added for this: an item that merely greyed out inside a menu would put the reason FURTHER from the user than the button it replaced. `Save results to my files` is also a button beside the pager once a result exists — the Query workspace's control, by name — so the menu item is where its refusal is read. Toggles say their state in the LABEL — `menuitem` carries no pressed state and `menuitemcheckbox` is the wrong shape for something that opens a panel. |
| `openExplorationOptions` / `chooseExplorationOption` / `explorationOption` | `explorationOptions.testkit.ts` | **Test-only.** Reach a menu item. ~130 assertions used to click these as toolbar buttons; a helper keeps the menu's shape in one place instead of a hundred. Not a query — the item is not in the document until the menu opens. |
| `useExplorationEviction()` / `evictExplorations(client, db, table?)` | `useExplorationEviction.ts` | Drops cached executions when a catalog changes. Registers with `features/catalog/`'s `onCatalogChange` rather than being called beside each `invalidateSchema` site — the shared layer must not import the leaf, and the next call site would be written by someone who had never heard of this cache. **Evicts what is on screen too**: a stale execution must not be served at all, so `resetQueries` (not `removeQueries` — removal only re-runs an observed query if something re-renders afterwards, which is an accident to depend on) clears the entry and refetches every observed one. That refetch is a second billed execution, which is why the eviction is as NARROW as the signal allows: a caller that names a table evicts only explorations of that table, so creating a view beside an exploration costs nothing. Saved-query sources go on every change — arbitrary SQL, no parser. **Mounted once in `ProtectedLayout`**. |

### Tab state

| Symbol | File | Purpose |
|---|---|---|
| `useExplorationTabs(username)` | `useExplorationTabs.ts` | Ordered tabs, one active, `sessionStorage` persistence per user, `updateTab(id, fn)` (a description and the history entry it pushes must be written in ONE update), and `openTab` returning **null** at `EXPLORATION_TABS_MAX` so the caller can raise the cap dialog (SPEC-179 renders it). Starts with **no tabs**, unlike `useQueryTabs`' seeded "Query 1" — an exploration needs a source and there is none to guess. `activeTabId` always references an existing tab, or `''` for the legal empty state. |
| `readExplorationTabsState` / `writeExplorationTabsState` / `initialExplorationTabsState` **(internal — not on the barrel)** | `explorationTabs.ts` | The degrade-safe persistence behind it; a corrupt, old or foreign document is discarded **whole**, never partially applied — a half-restored exploration renders SQL from a description the user never built. Validation goes past shape to the fields the renderer BRANCHES on (filter operators, `valueKind`, sort direction, aggregate functions, and that every ledger value is a finite number), because "restorable" is not "renderable": an unknown operator renders `"a" undefined 'x'` and reaches StartQueryExecution. |
| `tabBytesScanned(tab)` | `explorationTabs.ts` | A tab's cumulative bytes, summed from a ledger keyed by **execution id**. That keying is what makes "a cache hit adds nothing" true by construction: a running total would have to *detect* a hit, and a detector can be wrong in the direction that overcharges. |

| `groupingOrderingViolation(ordering, grouping)` | `renderExplorationSql.ts` | The ONE ordering rule, returning the offending COLUMN rather than a message: the renderer wraps it in operator text SPEC-106 forbids rendering, the panel wraps it in a sentence a user may read. ### Colours, striping and transformers (SPEC-184)

| Symbol | File | Purpose |
|---|---|---|
| `computePageFormatting(formatting, columns, rows)` / `bandsOf(...)` | `formatting.ts` | Every cell's resolved colours and every row's band for one page. Precedence is weakest to strongest — type tint, band, then rules in order — with each layer overriding only the **property** it sets, which is what makes "a later rule wins on the same property" and "a rule beats the tint and the band" true with no special case. A **NULL matches nothing, including `<>`**. Bands are runs of consecutive equal rows over the **current page** and are keyed by JSON, so no separator or NULL placeholder can make two different rows collide. |
| `ruleRefusal(rule)` / `isRuleApplicable(rule, columns)` | `formatting.ts` | Why a rule cannot be applied, in user wording (the engine's own `SyntaxError` names offsets in a half-typed pattern — SPEC-106). | `transformCell(value, transformer)` | `formatting.ts` | The numeric, binary and URL renderings — called **at the cell and nowhere upstream**, which is how filtering, colouring, Calc and copy all keep reading the raw row. | `resolveUrl(template, value)` / `templateRefusal(template)` | `urlTransformer.ts` | The scheme allowlist, judged on the **resolved** URL. | `typeColour(type)` / `colourValue(token)` / `gradientShade(from, to, position)` | `formatting.ts` | Six Athena type families folded onto five legible tokens; a token as `var(--color-…)`; a gradient quantised to eleven steps. | `<ValuePanel type transformed>` | `ValuePanel.tsx` | The raw value, the transformed rendering and the column's TYPE, labelled apart — the type because colour must never be the only carrier of it (FR-003 AC3), the rendering because a panel showing only the transformed form leaves nobody able to see what they are filtering and copying. | `renderCopy(selection, columns, rows, options, rangeStart?)` | `renderCopy.ts` | A selection as clipboard text in six formats (SPEC-185).
