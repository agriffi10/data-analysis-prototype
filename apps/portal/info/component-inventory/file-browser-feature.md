# File-browser feature (`apps/portal/src/features/file-browser/`)

Part of the component inventory (`INDEX.md`, beside this file, is the router).

Public barrel: `features/file-browser/index.ts`.

### Services (all return `ServiceResult<T>`, never throw)

| Symbol | File | Purpose |
|---|---|---|
| `listFiles(bucket, prefix?, continuationToken?, abortSignal?)` | `fileBrowser.service.ts` | One page of folders + files, through `objects.list`. The route delimits and bounds the page; the signal stops the browser **waiting**, not the request on the wire (a Lambda invocation cannot be cancelled). |
| `getDownloadUrl({ bucket, key, fileName? })` | `fileBrowser.service.ts` | Presigned `GetObject` minted by `objects.downloadUrl`, signed by the caller's own assumed session and clamped to it. Returns `{url, expiresAt}` — the expiry is what tells an expired link from a denial. |
| `uploadFile({ bucket, key, body, contentType, overwrite?, onProgress?, signal? })` | `fileBrowser.service.ts` | Uploads one file by whichever path the **server** chose — `objects.upload` answers a single presigned `PUT` or a multipart plan, and the browser holds no threshold. Bytes go over **`XMLHttpRequest`** (`fetch` fires no upload-progress event), and every URL is minted immediately before it is redeemed. `onProgress` is the AGGREGATE across parts and is monotonic across a retry. |
| `createFolder({ bucket, prefix, name, overwrite? })` | `fileBrowser.service.ts` | Zero-byte `{prefix}{name}/` marker (`application/x-directory`), in ONE call — the collision check is the write route's own `Conflict`. |
| `deleteObject({ bucket, key, username })` | `fileBrowser.service.ts` | Single-object delete; refuses the prefix marker with no request at all. |
| `copyObject({ bucket, sourceKey, destKey, username, destBucket?, overwrite? })` | `fileBrowser.service.ts` | `objects.copy`; the collision `HeadObject` moved inside the route, so a copy costs one call. `destBucket` defaults to `bucket`; each end resolves to its own space. `ServiceResult<{ destKey }>`. |
| `moveObject({ bucket, sourceKey, destKey, username, destBucket?, overwrite? })` | `fileBrowser.service.ts` | `objects.move` — **ONE route** performing copy-then-delete. Two calls would put a closed tab between them, and versioning is off. Same-key no-op. |
| `firstFreeName({ bucket, prefix, baseName, kind })` | `fileBrowser.service.ts` | The first free `{name} (N)`, resolved server-side in one call where the browser walked up to 999 `HeadObject`s. Exhaustion is `NoFreeName`; anything else keeps its own code. |
| `objectExists({ bucket, key })` | `fileBrowser.service.ts` | Existence of an exact key → bool. The route answers 200 either way. |
| `getObjectMetadata({ bucket, key })` | `fileBrowser.service.ts` | `objects.metadata` → `ObjectMetadata` (size/type/mtime/etag/storage class/custom). The pairs travel as rows and are folded back into a record here. 404 → error. |
| `ensurePrefixMarker({ bucket, username })` | `fileBrowser.service.ts` | Idempotently create the user's `DO_NOT_DELETE.txt` root marker, in ONE call (a `Conflict` is the "already there" answer), once per session. |
| `isPrefixMarkerKey(key, username)` | `fileBrowser.service.ts` | Is this exact key the user's root marker? |
| `validateLeafName(name, label)` / `validateFolderName(name, parentPrefix?)` | `fileBrowser.service.ts` | One path-LEAF rule (non-empty, no surrounding spaces, no `/`, no control chars, not `.` or `..`) with the caller's own noun. `validateFolderName` is it with `Folder name`, plus the app-managed `system_settings` name refused at any depth and, given the parent, the app's own folder names refused inside `system_settings/` — a courtesy on the dialogs, not a boundary: uploads and pastes never call it (SPEC-173). |
| `uploadPercent(loaded, total)` | `fileBrowser.service.ts` | Clamp loaded/total to a 0–100 whole percent (zero-byte → 100). |


### Upload internals

Behind `uploadFile`. A feature calls neither these nor `uploadFile`: it enqueues through `useUploadQueue().enqueue`, the one upload path with cancel and a row in `UploadList`, and the queue calls `uploadFile`.

| Symbol | File | Purpose |
|---|---|---|
| `uploadParts(...)`, `PART_CONCURRENCY`, `PART_RETRIES` | `multipartUpload.ts` | The part loop behind `uploadFile`'s multipart branch: per-part minting, per-part retry with a re-mint, a monotonic aggregate progress that never falls across a retry, and a best-effort abort on cancel that deliberately does **not** carry the caller's signal. `PART_CONCURRENCY` × `UPLOAD_CONCURRENCY` is budgeted against the browser's per-origin connection limit, so neither is readable alone. |
| `putBytes`, `uploadCancelled`, `uploadRejection`, `UploadFailure` | `xhrUpload.ts` | The **one** module permitted to name `XMLHttpRequest`, shared by both upload paths and enforced by a named-list guard with a positive control. Reads a part's `ETag` (absent ⇒ `null`, never a throw) and tells an expired link from a denial — which is what stops a 403 at the tail of a long upload reading as a permissions fault. |

### Hooks

| Symbol | File | Purpose |
|---|---|---|
| `useFileBrowser(bucket, prefix?)` | `useFileBrowser.ts` | Paginated listing via `useInfiniteQuery`; merges/sorts pages for the picker, and exposes `page` — ONE server page at a time, folders first within it — for the browser, whose position is remembered per listing and clamped to the pages a refetch leaves. `goNext` advances only if a page actually arrived. Hides EVERY `DO_NOT_DELETE.txt` by basename at any depth in either bucket — no caller-supplied key (SPEC-173 FR-003). |
| `useFileSpace({username, connections, isLoading, userSpaceBucket, sharedSpaceBucket})` | `useFileSpace.ts` | Active file-browser **space** from `useConnections` + the `?space=` route param → `FileSpaceTarget {id,bucket,rootPrefix,kind,label}`; `selectSpace`/`fellBack`/`dismissFellBack`. Gone/revoked/not-yet-active space reconciles to personal (file-side analogue of `useActiveDatabase`) (SPEC-057). |
| `useFileUpload(bucket, prefix)` | `useFileUpload.ts` | Create-folder orchestration for `FileBrowser`: the folder-name collision warn-and-confirm, the error, and listing invalidation on success. Despite the name it uploads nothing — a new upload surface calls `useUploadQueue().enqueue(files, {bucket, prefix})`, which has cancel and shows each file in `UploadList`. `prefix` is the folder prefix ending in `/`, since each key is `prefix + file.name`. |
| `useObjectMetadata(bucket, key \| null)` | `useObjectMetadata.ts` | Per-object metadata via `useQuery` — the API's `objects.metadata` route, a server-side `HeadObject` — keyed per object; disabled when key is null. |
| `useDelete(bucket, prefix, username?)` | `useDelete.ts` | Deletes a selection file by file; a FOLDER is refused per item with `PlaneRequired` while the files beside it still go through. Aggregates a `DeleteSummary`, invalidates the listing. Never throws. |
| `useMove(bucket, sourcePrefix, username?)` | `useMove.ts` | Rename (single) + move (multi-select) orchestration; collision warn-and-confirm, source/dest invalidation. A FOLDER is refused per item. Aggregates a `MoveSummary`. |
| `useCopy(bucket, username?)` | `useCopy.ts` | Copy (multi-select) orchestration; **destination-only** invalidation (additive), collision warn-and-confirm, and the same-folder auto-number `{name} (N)` flow (resolved by `firstFreeName`, editable). A FOLDER is refused per item. Aggregates a `CopySummary` (SPEC-039). |
| `useSelection()` | `selectionContext.ts` | Read/mutate the current view's multi-select set (`toggle`/`selectAll`/`deselect`/`clear`, `count`, `isSelected`). Must be under a `SelectionProvider`. **`deselect(ids)` exists because a row can leave the listing without the prefix changing** — collapsing the `system_settings` group — and the provider's navigate-clear does not fire for that; the toolbar acts on the SELECTION, not on what is rendered, so an item left selected while hidden is still Delete-able. |
| `useUploadQueue()` | `uploadQueueContext.ts` | Read/drive the multi-file upload queue (`items`, `enqueue`, `cancel`, `dismiss`, `resolveOverwrite`, `resolveRename`, `clearFinished`). Must be under an `UploadQueueProvider` (SPEC-020). |

| `HIDDEN_BROWSER_FOLDERS` / `PICKER_LOCKED_FOLDERS` / `UNDELETABLE_ROOT_FOLDERS`, `isRootFolderNamed(folderPrefix, rootPrefix, names)`, `isUndeletableRootFolder(folderPrefix, rootPrefix)`, `undeletableRootFolderRefusal(folderPrefix, rootPrefix, action)`, `undeletableSelectionRefusal(items, rootPrefix, action)` | `protectedFolders.ts` | (Names of the three moving folders come from `lib/appManagedPaths.ts`, and every root-anchored comparison goes through its `appManagedPrefixes`, which answers for both homes of a moving folder.) The lists differ on purpose; read the file's note before unioning them. `athenaresults/` is visible, never a paste target, never deletable or a move source (SPEC-150); `saved_queries/` (SPEC-173) is visible AND pasteable and only undestroyable, and the refusal helper names the folder in the message. `archive/` (SPEC-172) is the inverse of `saved_queries/`: visible — the folder names ARE the archive ids — but never a paste target and never destroyed, and read-only INSIDE as well, which is a different question answered by `isWriteLockedPrefix` below. `undeletableSelectionRefusal` is the SELECTION-shaped one, feeding `Button.disabledReason` so the refusal is stated BEFORE the destructive confirm rather than after it (SPEC-186 FR-002) — it matches the folder itself only, never an ancestor, because a selection deletes what is named. |
| `isWriteLockedPrefix(prefix, rootPrefix, spaceKind)`, `writeLockRefusal(prefix, rootPrefix, spaceKind)` | `writeLockedPrefix.ts` | The app's FIRST prefix-based write gate (SPEC-172 FR-004): a rule about where the user is STANDING, not about a folder's name.
