# Foundations (`apps/portal/src/lib/`)

Part of the component inventory (`INDEX.md`, beside this file, is the router).
Public surface only — the code is the source of truth; verify signatures before relying on them.


| Symbol | File | Purpose |
|---|---|---|
| `apiRequest(route, opts?)` | `lib/apiClient.ts` | THE browser's one door to the API. Takes a ROUTE ID from the generated contract, never a URL — a call site that builds a path is outside the contract, the retry rule and the response type at once. Reads the origin at call time; bearer from an injected provider; `credentials: 'omit'`; a 30 s abort that sits ABOVE the function's own timeout so the server gives up first. A templated route's `params` are **required by the type** (a conditional rest tuple, not an optional field), so a missing one is a compile error rather than a literal `{placeholder}` on the wire; a value that is not ONE path segment is refused unsent as `UnsendableParameter`, because `%2F` and `.`/`..` both address a SIBLING route that answers 200 with the wrong shape. Never throws, never navigates, and puts no server text in `error.message`. |
| `apiRetryPolicy(route)` | `lib/apiClient.ts` | The only source of a TanStack Query `retry` value for an API-backed hook. Returns `false` for any route the contract does not declare idempotent — idempotency is a property of the ROUTE, never derived from the method. |
| `setAuthTokenProvider`, `setUnauthenticatedHandler` | `lib/apiClient.ts` | Injected once from `AppRoot.tsx`. The provider takes `forceRefresh`, because the 401 path forces one refresh and that is the browser's only refresh path. No provider, or a `null` token → `SessionExpired` with ZERO network requests. |
| `USER_FIXABLE_CODES` | `lib/errorMessages.ts` | Computed from `CODE_RULES` like the set below it. Holds the rule the module exists for: the generic "Contact the Administrator" sentence is reserved for a failure the user CANNOT act on, so a code marked user-fixable that resolves to it is a contradiction a guard can see. |
| `PASSTHROUGH_CODES` | `lib/errorMessages.ts` | Computed from `CODE_RULES`, never hand-listed. Exists to be intersected with the generated `API_ERROR_CODES`: a passthrough rule renders the service's own message, so an overlap would let server text reach a user through a rule written to prevent it. |
| `spaceFor(bucket, key)` | `lib/objectSpace.ts` | The one `(bucket, key) → SpaceRef` adapter — what lets every ported service keep `bucket` in its signature while the API resolves a space from verified claims. Deliberately dumb: the name it derives from the key's first segment is a HINT the server re-checks, so a wrong one is a 403, never someone else's data. |
| `ATHENA_RESULTS_FOLDER` / `ARCHIVE_FOLDER` / `SHARED_TABLES_FOLDER` / `DATA_QUALITY_REPORTS_FOLDER` / `SYSTEM_SETTINGS_FOLDER`, `MOVING_FOLDERS`, `appManagedPrefix(rootPrefix, folder)`, `appManagedPrefixes(rootPrefix, folder)` | `lib/appManagedPaths.ts` | The app-managed folders — two of them under a real `system_settings/` prefix, `shared_tables` and the data-quality reports folder at the space root — and two builders. The SINGULAR is where a folder IS and resolves a moving folder under `system_settings/`; the browser writes no app-managed path, so its callers are the data-quality services reading back the keys the plane wrote, and the sweep makes it the only sanctioned place to construct one. The PLURAL is what every root-anchored COMPARISON calls, and it answers one home per folder since the old homes were emptied. Callers of the plural: `protectedFolders.ts`, `archiveSelection.ts`, `writeLockedPrefix.ts`. Both builders branch on `MOVING_FOLDERS`, so a name that does not move never acquires a second home. The narrowing shrank the plural to one element and edited nothing else. A CI sweep refuses a new declaration or `${root}${name}/` construction outside this file. In `lib/` because several features consume it and the archive feature imports nothing from another feature. |
| `getIdToken(forceRefresh?)` | `lib/idToken.ts` | The signed-in user's Cognito ID token, which `apiClient` sends as a bearer. **Named for a JWT, not for credentials, deliberately** — there are no AWS credentials in the browser to name, and a module called `awsCredentials` invites putting some back. `forceRefresh` is what the two "refresh" affordances call (`useConnections.ts`, `useSharedSpaceAccessRecovery.ts`) to re-mint a newly-granted `shared_space_k` claim; dropping it leaves both controls spinning no-ops. |
| `queryClient` | `lib/queryClient.ts` | App-wide TanStack `QueryClient` (staleTime 30s, retry 1, no refetch-on-focus). |
| `configureAmplify()` / `isAmplifyConfigured()` | `lib/amplify.ts` | Configure Amplify from the runtime document, and whether it can be. FUNCTIONS, not a const + import-time side effect: the values arrive with the document, and `configureAmplify` runs from the bootstrap before the first render (SPEC-192). |
| `setReturnPath(path)` / `setReturnPathIfAbsent(path)` / `takeReturnPath()` | `lib/returnPath.ts` | Stash (always / only-if-empty) + consume a post-login return path. `IfAbsent` seeds a default (e.g. `/files`) at sign-in/up without clobbering an auth-gate-captured path. |
| `useCopyToClipboard(resetMs?)` | `lib/useCopyToClipboard.ts` | `{copied, copy(text)}` — writes to the clipboard and flags a transient confirm; never throws (insecure-context/denied = silent no-op). **`copy` RETURNS whether the write landed** (SPEC-185): swallowing is only safe for a caller whose confirmation IS the `copied` flag, and a caller that closes its dialog and announces success separately would otherwise report a refused write as a successful copy. Callers that render the flag ignore the return. |
| `toUserMessage(error)` | `lib/errorMessages.ts` | Maps any caught value / `ServiceResult` error `{message, code}` → friendly `{title?, message}` (app code → AWS/Cognito name → Athena pattern → generic "Contact the Administrator"). **The single source of error wording** — never surface `error.message` directly; route it here. Dev-only original-error console log (SPEC-106). |
| `toUserText(error)` | `lib/errorMessages.ts` | `toUserMessage(error).message` — the string, for the 40+ sites that wanted only that. Accepts a `{code?, message?}`-shaped value directly, so a call site never rebuilds the argument by hand (SPEC-155 FR-008). |
| `logBackgroundFailure(scope, error)` | `lib/errorMessages.ts` | Dev-only tagged console warning for a fire-and-forget promise nothing renders. One tag instead of seven hand-written `console.warn`s, and silent in production (SPEC-155 FR-006/007). |
| `toServiceError(err, fallback)` / `unwrap(result)` | `lib/serviceResult.ts` | The `ServiceResult` adapters shared by every service/hook: `toServiceError` maps a caught value → the failure branch (`{message, code}`), safely for a non-object throw; `unwrap` returns a result's data or throws its error (with `.code` preserved) — the one bridge for TanStack query/mutation fns. |
| `userSpaceBucket()` / `sharedSpaceBucket()` / `spaceBuckets()` / `userSettingsKey(username, file)` | `lib/userSpace.ts` | The two bucket env reads (call-time) + the protected `{username}/user_settings/{file}` key template — single source for the per-user read/write services. `spaceBuckets()` returns the `{user?, shared?}` pair most call sites actually want; each getter returns `''` when unset, and the pair omits an unset key (SPEC-155 FR-006). |
| `readJsonDocument<T>({bucket, key, parse, onMissing?, fallbackMessage})` / `writeJsonDocument({bucket, key, value, fallbackMessage})` | `lib/s3Json.ts` | The one read/write pair behind every `user_settings/`-style JSON document (saved queries, history, notifications, shared connections, data-quality report + runs) — over the API's document routes since SPEC-198, with all four exports unchanged. The username directory and the feature-flag document are NOT among them: neither prefix belongs to a user, so each has a route of its own. `parse` must be TOTAL — a malformed body is that document's business, not an exception; `onMissing` is what a 404 means *here* (omit it and a miss is an ordinary failure). Writes are `PutObject` only, never a delete. `ServiceResult`, never throws (SPEC-155 FR-001). **A read-modify-write must classify first** (`classifyDocument` below) and reach `writeJsonDocument` only for a body it could read or has already quarantined (SPEC-159). |
| `classifyDocument<T>({body, version, empty, isReadable})` | `lib/s3Json.ts` | The three-way write-path parse for a versioned settings document → `DocumentParse<T>` = readable / `newer` / `unparseable`. Absent or zero-byte is the EMPTY document; the version is checked **before** the shape, so a newer document classifies `newer` whatever else it contains. `newer` must never be overwritten or quarantined — that would downgrade what a newer tab wrote (SPEC-159 FR-001). |
| `quarantineDocument({bucket, key, now?})` | `lib/s3Json.ts` | Copies an unreadable document aside, server-side, to `{key}.unreadable-{ISO basic UTC}-{token}.json` — same prefix, so no IAM change, and the bytes never enter the browser. The random token is load-bearing: without it a racing quarantine overwrites the evidence (see `docs/decisions/storage.md`). Returns the quarantine key; a failure the caller **must** treat as fatal — never overwrite after a failed copy (SPEC-159 FR-002/003). |
| `WriteOutcome<T>` | `lib/s3Json.ts` | `ServiceResult<T> & {recovered?: boolean}` — a read-modify-write's result plus whether the previous document had to be quarantined to get there. Lets a *successful* write still report that the user's earlier content is gone (SPEC-159). |
| `parseS3Url(url)` | `lib/s3Url.ts` | `s3://bucket/key` → `{bucket, key}` or `null`. Trims, accepts `undefined`, and requires a non-empty key. One implementation for the Athena output location, a Glue `LOCATION`, and the rail's source-files deep link (SPEC-155 FR-006). |
| `formatBytes(bytes?)` / `formatCount(n)` / `formatDurationMs(ms?)` / `formatAbsoluteDate(value)` / `formatRelativeTime(iso, now?)` | `lib/format.ts` | The display formatters more than one feature needed. `formatRelativeTime` falls back to a **pinned en-US** absolute date (`Jan 15, 2026`) beyond a week, so the string does not shift with the viewer's locale. `formatBytes` joined them in SPEC-176 FR-004 — the query status bar and the Data Explorer render the same scanned-bytes figure, so neither feature can own it; it keeps its `undefined` → em-dash handling and its SPEC-155 FR-007 TB ceiling, asserted against `formatSize` in `lib/utils.test.ts`. The file browser's `formatSize` stays in its feature. |
| `loadRuntimeConfig()` / `configValue(key)` / `missingRequiredConfig()` / `isPortalConfigured()` | `lib/runtimeConfig.ts` | The single door to configuration, read at CALL time from `/config.json`. A dev build falls back to `import.meta.env`; a production build **throws** before the load resolves rather than returning `undefined`. `setRuntimeConfigDocument` is the loader's writer and the seam `src/test/seedRuntimeConfig.ts` uses (SPEC-192). |
| `VITE_NAME` / `devFallbackValue(key)` / `warnIfMisconfigured()` | `lib/env.ts` | The DEV FALLBACK and nothing else since SPEC-192. `VITE_NAME` is the single list of variable names (`PortalEnvVar` derives from it); every reference sits inside an `import.meta.env.DEV` branch so the bundler deletes the tables, asserted by `npm run check:bundle`. |
| `NO_KEY` | `lib/queryKeys.ts` | The `'__none__'` placeholder a TanStack key uses in place of a null username, so a disabled query still has a stable key. Replaces the string literal at all 8 sites (SPEC-155 FR-006). |
| `sqlLiteral(value)` / `sqlIdentifier(name)` / `quoteIdentifierIfNeeded(part)` + `TRINO_RESERVED_KEYWORDS` | `lib/sql.ts` | SQL escaping for queries the BROWSER composes (SPEC-178). `sqlLiteral` is the **Trino/DML** rule — doubles the single quote — and is NOT `cpcommon.ddl.literal`, the Hive/DDL escaper that backslashes; Trino has no backslash escape in a plain string literal, so the wrong one renders a backslash into the value and the predicate silently never matches. `sqlIdentifier` double-quotes, doubling an embedded double quote. Column names go through it and must **not** be checked against `CATALOG_IDENTIFIER_RE` — that rule describes names the app CREATES, and a column name is not catalog-safe. `quoteIdentifierIfNeeded` (SPEC-244) is what autocomplete inserts: the part unchanged only when already lowercase, `[a-z_][a-z0-9_]*` and not in `TRINO_RESERVED_KEYWORDS` (Trino's 83 reserved words), `sqlIdentifier` otherwise — a **superset** of that list is safe, a subset is not, and it is a Trino rule that never belongs near Hive DDL. |
| `CATALOG_IDENTIFIER_RE` / `CATALOG_IDENTIFIER_RULE` | `lib/catalogIdentifier.ts` | The catalog-safe identifier rule (`^[a-z][a-z0-9_]{2,62}$`, = the SPEC-033 username rule) and its human-readable hint — one source of truth for the view / table / shared-connection dialogs and the directory's own re-check. `PARTITION_KEY_NAME_RE` / `PARTITION_KEY_NAME_RULE` beside them are the partition-key row's rule, the same alphabet and ceiling from ONE character (`^[a-z][a-z0-9_]{0,62}$`), because a key is named after a `dt=`-style folder. Both regexes mirror `cpcommon.config`, held equal by `lambdas/test_catalog_identifier_browser_mirror.py`. Moved out of `features/query/` by SPEC-155 FR-005. |
| `discardPayload(result)` | `lib/serviceResult.ts` | Drops a successful `ServiceResult`'s payload, keeping the failure as it is. Used by the six enqueue services whose callers are written against `ServiceResult<void>` — the routes answer `{requestId}`, and widening six signatures would touch every hook and dialog above them for a value none of them reads. |
| `PALETTE` / `CONTRAST_PAIRS` / `DECORATIVE_TOKENS` / `FIXED_LANDING_CTA` / `ColorToken` | `lib/palette.ts` | The ONE place a colour value is written down, both themes. `index.css` is the source and this is pinned to it by `lib/contrast.test.ts`, which measures every declared pairing in both themes and fails naming the pair and its ratio. Every token is either in a pairing or in `DECORATIVE_TOKENS` with its reason — a token in neither fails. Import the values only where a CSS variable cannot go (a gradient's mix, Monaco's theme); everywhere else use the Tailwind token utility (SPEC-210). |
| `contrastRatio(a, b)` / `relativeLuminance(hex)` | `lib/contrast.ts` | WCAG 2.2 luminance and ratio, pure and DOM-free — which is why they can exist where axe's `color-contrast` rule cannot (jsdom has no layout engine). Both **throw** on anything that is not `#rgb`/`#rrggbb`: a permissive parse returns 21 for `'zzz'` and a plausible 1.48 for a five-digit hex, so a typo'd pairing would clear every floor with nothing red (SPEC-210). |
| `useTheme()` / `setThemePreference(next)` / `THEME_STORAGE_KEY` | `lib/useTheme.ts` | The theme preference (`light`/`dark`/`system`, anything else read as `system`), `localStorage`, per browser. A module store read through `useSyncExternalStore`, deliberately **not** a Context provider — switching must re-render subscribers and remount nothing. Both the read and the write are wrapped; with storage throwing the control still works for the session. `public/theme-init.js` makes the same two writes before the first paint (SPEC-210). |
