# Table-builder feature (`apps/portal/src/features/table-builder/`)

Part of the component inventory (`INDEX.md`, beside this file, is the router).
Public surface only — the code is the source of truth; verify signatures before relying on them.


| Symbol | File | Purpose |
|---|---|---|
| `enqueueTableBuild(req)` | `tableBuild.service.ts` | The browser's only table-builder call: builds the SPEC-067 envelope (`idToken` + `space` + `tableName` + `partitionKeys` + `requestId`) and FIFO-sends to `VITE_TABLE_BUILD_QUEUE_URL` (`MessageGroupId` = `space.database`, dedup = `requestId`) via `getSqsClient`; `ServiceResult<void>` (enqueued ≠ created), never throws (SPEC-071). |
| `suggestTableName(folder)`, `isValidTableName(name)` | `tableBuild.service.ts` | Pure: sanitize a folder name to a catalog-safe suggestion / test a name against `CATALOG_IDENTIFIER_RE` (UX only — server re-validates) (SPEC-071). |
| `buildPartitionKeys`, `buildPartitionKey`, `validateDraftKey`, `emptyDraftKey`, `parseValues` | `partitionKeys.ts` | Pure draft→wire partition-key logic + per-row validation (name/uniqueness, integer/date/string-enum config); empty list ⇒ valid flat `[]` (SPEC-071). |
| `CreateTableButton` | `CreateTableButton.tsx` | File-browser toolbar action → opens the dialog, enqueues for the active space + prefix, success/error `Toast` (SPEC-071). Takes `rootPrefix` so it can refuse at the space root; eligibility is otherwise enforced server-side. |
| `createTableRefusal(prefix, rootPrefix)` | `createTableRefusal.ts` | The one pre-flight refusal on this control, on `writeLockRefusal`'s predicate-with-its-words precedent. A table's `LOCATION` is read recursively, so a build at the space root SUCCEEDS over `athenaresults/`, `saved_queries/`, `user_settings/`, `shared_files/`, `shared_tables/` and `archive/` — succeeding is what makes it worth blocking. Compares with `isAtRoot`, never a second `===`. The control plane raises `location_is_space_root` for the same case, on creates only (refusing a refresh would strand a root table already in a catalog). |
| `CreateTableFromSpaceDialog` | `CreateTableFromSpaceDialog.tsx` | The folder step the Files toolbar does not need — space + folder, for a surface with no folder in view. Takes a **structural `BuildableSpace`**, never `usableSpaceTargets`: rebuilding the list from the connections would hand back the shared spaces the caller's `sharedWorkspaces` filter had just removed, the live defect SPEC-185 found in the Query workspace's save destinations. `allowCurrentParent` is deliberately absent, and the picker's `currentParentMessage` carries `CREATE_TABLE_AT_ROOT_REFUSAL` so the root refusal reads as itself rather than as move/copy's "These items are already here". |
| `useCreateTableFromSpace()` | `useCreateTableFromSpace.ts` | The two-step flow behind it — `folder` → `name` → enqueue — reusing the SAME `CreateTableDialog` for step two and the same one `enqueueTableBuild` call. A failure keeps the name step up with the reason on it, so a retry does not re-choose the folder. `suggestedNameFor` is the folder's own last segment. |
| `useCatalogCatchUp()` / `armCatalogCatchUp(db, table)` | `useCatalogCatchUp.ts` | `arm` after a successful enqueue; the hook re-reads that catalog on the next window focus. **The enqueue is not the event** — a build lands minutes later and announces itself in a notification, so without this a table dropped and rebuilt under the same name leaves the Data Explorer resolving to the pre-drop execution. **Module state, mounted once in `ProtectedLayout`**: both controls that enqueue a build unmount when the user leaves that route, so a per-component arm died with the control that set it — enqueue from Files, walk to the Explorer, nothing fires. The table IS named (the plane creates exactly the name asked for or fails), which keeps the re-read from resetting every other exploration of the database. Residual: `focus` fires on blur→focus only, so a user who never leaves the window gets no catch-up until they do. |
| `CreateTableDialog` | `CreateTableDialog.tsx` | Name prompt (suggested + validated) + optional partition-keys section; Confirm gated on name **and** keys valid; inline submit-error banner (SPEC-071). |
| `PartitionKeysField` | `PartitionKeysField.tsx` | Controlled, ordered, reorderable/removable partition-key rows (name + type `<select>` + per-type projection config) with focus management + labelled dynamic rows (SPEC-071). |
| `TableBuildRequest`, `PartitionKey`, `DraftPartitionKey`, `PartitionKeyErrors`, `PartitionType`, `PartitionKeysResult` | `tableBuild.types.ts`, `partitionKeys.ts` | The request + wire partition-key shapes (match the SPEC-067 contract) + the editor's draft/error/result types (SPEC-071). |
| `enqueueTableRefresh(req)` | `tableBuild.service.ts` | The refresh half of the same queue (SPEC-145): `mode: 'refresh'` + `partitionKeys: []` (a refresh reconstructs the table's keys, never redeclares them) + `allowRemovals` **only when true** (SPEC-144 validates the flag, so absent ≠ false); `requestId`/ID token minted inside, queue URL read at call time. `ServiceResult<void>`, never throws. |
| `useTableRefresh(notify, linked?)` | `useTableRefresh.ts` | Dialog + enqueue state for Refresh table, shaped like `useTableShare`: `{target, busy, error, open, close, submit}`; `open(database, table, pending?)` takes the **`GlueTableSummary`** (the request's space comes from its `location`). `linked` is the derived notification-link target + the callback that retires it — the link-borne dialog is derived from the URL, never opened from an effect. Also owns the rail invalidation: once on submit, once on the next window focus, then disarmed (SPEC-145). |
| `RefreshTableDialog` | `RefreshTableDialog.tsx` | The refresh confirmation on `ConfirmDialog`: what a refresh does/doesn't do, the always-unchecked removals opt-in with its consequence copy, and — in the link-borne state — the named columns plus `confirmDisabled` until the box is ticked (SPEC-145). |
| `parseTableLocation(location)` | `tableRefresh.location.ts` | Pure: `s3://{bucket}/{prefix}` → `{bucket, prefix}` with a normalised trailing slash, `null` otherwise. The Query workspace's only route from a Glue table to its folder (SPEC-145). |
| `parseRefreshLink(search)`, `MAX_LINKED_COLUMNS` | `tableRefresh.link.ts` | Pure: parses `?refreshTable={db}.{table}&removed={names}` from the **raw** query string (never `URLSearchParams` — it decodes, and the names are percent-encoded around a comma separator). Identifiers validated against `CATALOG_IDENTIFIER_RE`, **column names deliberately not** (they are never catalog-safe); capped at 20 (SPEC-145). |
| `TableRefreshRequest`, `TableRefreshTarget`, `PendingRemoval` | `tableRefresh.types.ts` | The refresh request shape, the dialog's target (`pending` present ⇒ opened from a `columns_removed` link), and the parsed link. Never persisted (SPEC-145). |
| `TableBuildSpace`, `TableBuildMode` | `tableBuild.types.ts` | The space shape (extracted from `TableBuildRequest`, so a refresh caller can build one from a Glue table's location rather than the folder in view) and `'create' \| 'refresh'`. `TableBuildRequest.mode` is optional; absent ⇒ create (SPEC-143). **`enqueueTableBuild` does not forward it** — the body is built field by field, and SPEC-145 adds the refresh caller. |
