# Catalog feature (`apps/portal/src/features/catalog/`)

Part of the component inventory (`INDEX.md`, beside this file, is the router).
Public surface only — the code is the source of truth; verify signatures before relying on them.

Public barrel: `features/catalog/index.ts`. The shared catalog & execution layer (SPEC-176): the
Glue schema reader, the Athena start/poll/results/cancel layer, the space list and the column-width
store — everything both the Query workspace and the Data Explorer need. **No UI** and no feature
domain of its own; `features/query/` and `features/data-explorer/` compose it and may not import
each other (enforced by the ESLint layering rule). All services return `ServiceResult<T>`, never
throw.

### Services

| Symbol | File | Purpose |
|---|---|---|
| `runQuery({ sql, database?, username })` | `athena.service.ts` | `POST /v1/queries`. The workgroup, the results location (`{username}/system_settings/athenaresults/`) and the caller's identity are derived SERVER-SIDE from the verified claim — the wire has nowhere to name any of them, which is why `outputLocation` is gone and `username` stays on the signature only so no call site changed. Type-agnostic (SELECT + DDL). `ServiceResult<{ queryExecutionId }>`. |
| `getQueryStatus(id)` | `athena.service.ts` | `GET /v1/queries/{id}` → `QueryStatus`. A FAILED or CANCELLED execution is a **200**, and `stateChangeReason` arrives byte-identical: it is data about the query, and six authored sentences in `errorMessages.ts` are chosen by reading it. Statistics are `null` while non-terminal, never `0`. An execution that is not the caller's, or that Athena does not know, is **404 `NotFound`**, one body for both. |
| `getQueryResults({ queryExecutionId, nextToken?, maxRows? })` | `athena.service.ts` | `GET /v1/queries/{id}/results` → typed `QueryResultPage`. The `+1` overfetch, the 1000 clamp and the first-page header-row drop now happen server-side; the pager still walks `nextToken` here. Reading before SUCCEEDED is **409 `QueryNotFinished`**, and the caller's own gate is still what stops it. Someone else's execution is **404 `NotFound`** at any state, a running one included. A cell is **`null` for SQL NULL and `''` for an empty string** — the two used to be collapsed here, and no consumer could reconstruct the difference. |
| `stopQuery(id)` | `athena.service.ts` | `POST /v1/queries/{id}/stop` → CANCELLED. Idempotent **despite being a POST** (the id is in the path), and stopping an already-terminal execution is a success. The API proves the execution is the caller's before stopping it, so an unknown or foreign id is `NotFound`. Every call site discards the result. |
| `isTerminalState(state)` | `athena.service.ts` | Is a `QueryState` terminal (SUCCEEDED/FAILED/CANCELLED)? |
| `runStatementToCompletion({ sql, database, username, signal? })` / `isAbandoned(result)` / `ABANDONED_CODE` | `athena.service.ts` | Run-and-poll-to-terminal helper for background statements (View DDL, Drop, Create view). An abandoned poll is its OWN code, so a caller says nothing rather than borrowing the upload feature's "Upload cancelled." (SPEC-044/048). |
| `getTableDdl({ database, table, username, isView? })` | `athena.service.ts` | `SHOW CREATE TABLE` (or `SHOW CREATE VIEW`) → the assembled DDL (SPEC-044/048). |
| `getDatabase(name)` / `listTables(name)` | `glue.service.ts` | `GET /v1/catalog/databases/{db}` and `…/tables`. Missing DB → `NotFound` / empty list, never thrown — deliberately different answers, because a not-yet-created database is an empty schema browser rather than a banner. `listTables` keeps returning the whole list and walks the API's `nextToken` internally, so its callers never learned the API pages. |

### Hooks, keys, types, constants

| Symbol | File | Purpose |
|---|---|---|
| `useQueryExecution(id \| null, {stopOnError?, watchKey?})` → `{status, error, stillRunning}`, plus `isQueryStillRunning(value)` | `useQueryExecution.ts` | Polls `getQueryStatus` via `refetchInterval` until terminal; disabled when null. One watch lasts `MAX_POLL_DURATION_MS`, and the first read after that mark decides: still running sets `stillRunning` (a `QueryStillRunning` shaped for `toUserMessage`), a failed read ends it with `error`. Never the clock alone, since the poll pauses while the page is hidden. The verdict is hook state, so a new watch of the same id looks again, and a changed `watchKey` (a stable name for the watcher) starts one (SPEC-234). Retries a failed request per `apiRetryPolicy('athena.status')`; `stopOnError` disables the query once it has failed, so neither the interval nor a reconnect asks again. |
| `useQueryResults(id \| null, maxRows?)` | `useQueryResults.ts` | Prev/Next pager over results via `useInfiniteQuery`: the current page's `columns`/`rows`, `pageIndex`/range, `hasPrev`/`hasNext`, `goPrev`/`goNext` (Next fetches forward, Prev from cache), loaded/total counts (SPEC-038). The remembered per-execution page is **clamped to the pages actually cached** (SPEC-180): an unobserved execution loses its pages at `gcTime` and refetches from page 1, and an absent page is indistinguishable from an empty one — a result WITH rows rendered as "No rows returned". |
| `getQueryRowCount(id)` | `athena.service.ts` | `GET /v1/queries/{id}/row-count` → `QueryRowCount` `{rowCount, pending}`: Athena's own count of the rows a succeeded SELECT returned, one call, no scan, no rows shipped. `pending` means ask again; `rowCount: null, pending: false` means Athena does not count this statement (SPEC-231). |
| `useResultRowCount(id \| null)` | `useResultRowCount.ts` | A succeeded query's exact total — never an estimate, never capped. Asks `getQueryRowCount` first, re-asks a pending count on `ROW_COUNT_PENDING_DELAYS_MS`, and walks every page at `ROW_COUNT_PAGE_SIZE` only where Athena does not count; each walked page is a **billed API call**. A failed ask leaves `total` null, `isCounting` false, and walks nothing. Keyed apart from the visible pager so it never perturbs it; `{total, isCounting}` (SPEC-080, SPEC-231). |
| `useColumnWidths(executionId, columnCount)` | `useColumnWidths.ts` | In-memory `Record<executionId, number[]>` width store keyed by execution id, so widths survive paging **and** tab switches; `widths`/`setWidth` (clamped ≥ `MIN_COLUMN_WIDTH`)/`resetColumn` (SPEC-064). |
| `ColumnResizeHandle({column, columnName, width, onResize, onReset})` | `ColumnResizeHandle.tsx` | The focusable `role="separator"` on a header's right edge — pointer drag, double-click reset, Arrow nudge by `COLUMN_RESIZE_STEP_PX`, and the `aria-valuenow`/`aria-valuemin`/`aria-valuemax` a focusable separator requires (`MAX_COLUMN_WIDTH`, which both width stores clamp to — ARIA's default max of 100 sat below every real width). Handled Arrows **stop propagating**, or a grid listening above it moves its cell cursor too. Moved here from `features/query/` by SPEC-180 (two sibling features draw grids and neither may import the other) and **generic over its column key**: the Query workspace passes an index (a `SELECT` may return duplicate names), the Data Explorer a name (its geometry outlives the execution). The only UI in this layer. |
| `useRunDdl({username, appendEntry, toast})` | `useRunDdl.ts` | One background-DDL path: runs a statement to completion, records it, toasts the outcome and invalidates the target schema — naming the one catalog object it changed (`RunDdlArgs.table`), so a per-table cache evicts that and not the rest. **Moved here from `features/query/`** because the Data Explorer creates views too, and a leaf importing a leaf is the coupling the layering rule forbids; only `appendEntry`'s type changed, to a structural `RecordStatement`. |
| `buildCreateViewSql(database, name, body)` | `createView.ts` | The one `CREATE OR REPLACE VIEW` this app writes, now that two surfaces write one. Both identifiers are quoted with the **Trino** escaper (`lib/sql.ts`), never the DDL one — Athena parses `CREATE VIEW` with Trino, where a backtick is an error rather than a quote. The database is the one that matters: a shared space's name is not format-checked anywhere server-side, so a crafted name reaches a member's space list and from there this statement, under their own Athena credentials. |
| `CreateViewDialog` | `CreateViewDialog.tsx` | Name prompt for a view, validated against `CATALOG_IDENTIFIER_RE`; the target database is shown read-only, never chosen. Moved here from `features/query/` with the DDL path above. |
| `useSchema(db \| null)` + `invalidateSchema(client, db)` + `onCatalogChange(listener)` | `useSchema.ts` | DB + tables for a schema browser; the invalidation helper that refreshes it after DDL (taking an optional `table`, which is the difference between a per-table consumer re-reading one thing and re-reading everything — in Athena bytes, for the Data Explorer); and the registration by which anything ELSE that caches per-database can hear the same signal. The registration exists because the shared layer must not import the leaf feature — the Data Explorer's execution cache has to be evicted on a rebuild, and `features/catalog/` reaching into `features/data-explorer/` to say so would point the layering the wrong way. Not a query-cache subscription: TanStack emits no event for invalidating a key nothing has cached. |
| `useAllSchemas(databaseNames)` | `useSchema.ts` | Every accessible database's schema at once (`useQueries`, sharing `useSchema`'s per-DB cache keys) → `DatabaseSchema[]`; failed DBs omitted (SPEC-077). |
| `partitionSchema(tables)` | `schema.partition.ts` | Pure split of a database's Glue objects into `{tables, views}` (`tableType === 'VIRTUAL_VIEW'` → views), keeping input order within each group. The one split behind the Query rail's two groups and the Data Explorer's source picker. Not in the barrel: import it from the file. |
| `useQuerySpaces()` | `useQuerySpaces.ts` | The one list of spaces a catalog consumer reads from and writes into — the user's own first, then each usable shared connection — as `QuerySpace[]` (SPEC-173 FR-005). |
| `catalogKeys` | `catalogKeys.ts` | Key factory (`all`/`schema`/`execution`/`results`/`rowCount`), rooted at `['catalog']` — never hand-build keys. Rooted away from `['query']` on purpose: a namespace naming a feature the module no longer belongs to would let `invalidateQueries({queryKey: queryKeys.all})` reach into another feature's caches (SPEC-176 FR-003). |
| `useSaveResults({spaces, username, outputLocation, executionId, linkedSavedName, toast})` | `useSaveResults.ts` | Saves a succeeded execution's results into a chosen space, routing on the format: **CSV** is the server-side `CopyObject` it always was, so ALL rows travel however few pages loaded, and the other three are handed to the results-conversion plane and arrive as a notification. A collision returns a warn-and-confirm on either path — the conversion path asks first, through an `objects.exists` pre-flight in which a **403 counts as occupied**, and the plane's conditional write stays the authority. **The plane's destination prefix is relative to the space root**, so the hook slices it; passing the picker's absolute one writes a doubled root that nothing refuses. `executionId` is a parameter rather than parsed back out of `outputLocation` — the plane re-reads the execution, so a disagreeing id converts a different result than the one on screen. Moved here from `features/query/` by SPEC-185, because the Data Explorer's export needs it and may not import that feature. **`spaces` is a parameter**, not a `useQuerySpaces()` call inside: the hook's own list was unfiltered, so the Save-results dialog offered a colleague's space as a write target with `sharedWorkspaces` off. Both views now gate it, and both have a registry row. |
| `SaveResultsDialog` | `SaveResultsDialog.tsx` | The destination picker, a validated file-name field and a **Format** choice, keyed per space so browsing state resets. The primary button reads *Save here* for CSV and *Convert and save* otherwise, so the wait is announced before the click. With `resultsConversion` off the select is **absent** and the dialog is the one it was before. Moved with the hook (SPEC-185). |
| `enqueueResultsConversion(request)` | `resultsConversion.service.ts` | The browser's only results-conversion write: `POST /v1/enqueue/results-conversion` through `apiRequest`, echoing the caller's `requestId` back. Success means **enqueued**, not converted — nothing is written when it resolves, which is why the caller invalidates no listing and the notification is the completion channel. Non-idempotent, so nothing retries it. |
| `ResultsFormat` | `catalog.types.ts` | `'csv' \| 'parquet' \| 'json' \| 'xlsx'`. The generated enqueue contract carries the same four since SPEC-239 gave the plane a CSV writer, so nothing narrows at the boundary. csv still COPIES unless the file keeps a subset of the result's columns, which a copy cannot produce. |
| `normalizeResultsName(name, format)`, `RESULTS_FORMATS` | `catalog.format.ts` | Appends the chosen format's extension unless already typed (case-insensitively), never doubling it, and **replaces** another of the four rather than stacking onto it — the format is a control the user can change after typing a name. A dot-segment that is not one of the four (`sales.2026`) is left alone rather than guessed at. `RESULTS_FORMATS` is the one label/extension map, read by the `<select>`, the toast and this function. Replaced `normalizeCsvName` in SPEC-223. |
| `normalizeColumnType(type)` | `catalog.format.ts` | Maps Athena/Presto engine type names (`varchar`, `integer`) back to the Glue/Hive names the schema rail shows, so a column reads the same in the results header as in the catalog. |
| `QueryState`, `QueryStatus`, `QueryColumn`, `QueryResultPage`, `GlueColumn`, `GlueTableSummary`, `DatabaseSchema`, `QuerySpace` | `catalog.types.ts` | The execution, result-page, Glue and space types. `DatabaseSchema` lives here rather than beside the completion provider that consumes it, because `useAllSchemas` produces it and a catalog module may not import a leaf feature (SPEC-176 FR-001). |
| `POLL_INTERVAL_MS`, `MAX_POLL_DURATION_MS`, `DEFAULT_MAX_ROWS`, `ROW_COUNT_PAGE_SIZE`, `ROW_COUNT_PENDING_DELAYS_MS`, `DEFAULT_COLUMN_WIDTH`, `MIN_COLUMN_WIDTH`, `MAX_COLUMN_WIDTH`, `COLUMN_RESIZE_STEP_PX` | `catalog.constants.ts` | Athena's polling cadence and guard, the service-level page size, the fallback row-count walk's page size and the re-ask schedule for a pending count, and result-column sizing. The **display** page-size constants are a workspace preference (SPEC-087) and stay in `features/query/`. |
