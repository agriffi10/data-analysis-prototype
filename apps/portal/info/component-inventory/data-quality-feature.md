# Data-quality feature (`apps/portal/src/features/data-quality/`)

Part of the component inventory (`INDEX.md`, beside this file, is the router).
Public surface only — the code is the source of truth; verify signatures before relying on them.


| Symbol | File | Purpose |
|---|---|---|
| `enqueueQualityCheck(req)` | `dataQuality.service.ts` | One `apiRequest('dataQuality.enqueue')` carrying `requestId` + `space` + `location`, echoing the caller's own id back. The group id is still the hashed `{bucket}/{location}` — with the bucket now resolved server-side from the space kind rather than taken from the body — and is pinned by a golden vector. |
| `useDataQualityCheck()` | `useDataQualityCheck.ts` | `{start, isPending}` — mints the request id, enqueues, and reports the outcome twice over: it RESOLVES to `true`/`false` (SPEC-124) and, unless `opts.toast === false`, toasts (success, or `toUserMessage` on failure). `toast: false` suppresses the SUCCESS toast only; a failure always toasts, so no caller re-implements the wording. Ref-guarded against re-entry (SPEC-113). The toast stops at "started" because the *result* arrives as a notification carrying the report link (SPEC-114). |
| `DataQualityDialog` | `DataQualityDialog.tsx` | Read-only-check confirmation on the shared `ConfirmDialog`: names the target space-relative, states plainly that nothing is modified, locks while in flight; closes either way (SPEC-113). |
| `getQualityReport(bucket, space, requestId)` | `dataQualityReport.service.ts` | Reads `{space}/_data-quality-reports/{requestId}/report.json`; a missing or structurally-invalid document is a typed failure, never an empty "clean" report. Also exports `reportKey` (SPEC-113). |
| `useDataQualityReport(space, requestId)` | `useDataQualityReport.ts` | Resolves the `:space` segment (own username wins; shared names only when it differs), then fetches. Never fetches for an unreachable space. The own username resolves without the connections list, so a personal report does not wait for it. A space the list lacks is refused only on a read of it after the link (`useSpaceLinkPending`). Also exports pure `resolveSpace` (SPEC-113). |
| `DataQualityReportPage` | `DataQualityReportPage.tsx` | The `/data-quality/:space/:requestId` view: verdict banner, summary tiles (2×2 → 4-up), top issues, columns table→cards (`useIsMobile` mount-gated), cross-file disagreements, qualifier callouts, metadata footer. Every approximate/skipped/not-computed figure renders with its reason (SPEC-113). |
| `DataQualityReport` + figure types | `dataQuality.types.ts` | The report shape, mirroring `dqcommon/report.py` byte-for-byte, plus the `isSkipped`/`isNotComputed`/`isUnmeasured`/`isTypedColumn` narrowing helpers that keep "could never apply" and "tried and failed" from collapsing (SPEC-113). |
| `asSentence`, `isApproximateIssue`, `sourceFolderPrefix`, `formatRatio`, `locationLabel`, `splitLocation` | `dataQuality.format.ts` | Report presentation helpers: sentence-case a Lambda-authored reason fragment, classify a top-issue line as exact vs approximate (pinned to `report.py::top_issues` wording by test), reduce a file key to its parent folder, percentages that distinguish none from rounds-to-none (SPEC-113), and `splitLocation` — a location as truncatable parent + non-shrinking leaf, the head-truncation construction used by the run row and the start dialog (SPEC-123/124). |
| `getRunsIndex(bucket, space)` | `dataQualityRuns.service.ts` | Reads `{space}/_data-quality-reports/index.json` and stamps `space` onto every entry (the object doesn't carry its own). A missing, corrupt or structurally-wrong index is an EMPTY SUCCESS, never an error; a malformed entry is dropped without losing the rest. Also exports `runsIndexKey` (SPEC-123). |
| `useDataQualityRuns()` | `useDataQualityRuns.ts` | `{runs, isLoading, error, refresh}` — every completed check across the personal space + each usable shared space, merged and sorted newest-first. One unreadable space is skipped with a warning; only an all-spaces failure surfaces an error. Also exports pure `runsSources` (SPEC-123). |
| `DataQualityRunRow` | `DataQualityRunRow.tsx` | One run as a whole-row link to `/data-quality/{space}/{requestId}`, accessible-named by location. Verdict = dot + label (never colour-only); a `Sampled` chip whenever `hasApproximateFigures`. Location splits into a truncatable parent + non-shrinking final segment (SPEC-123). |
| `DataQualityPage` | `DataQualityPage.tsx` | The `/data-quality` list: verdict filter, 10/page `Pager`, refresh, four states, the completed-checks-only footer line pointing failures at `/notifications` (SPEC-123), and the **New quality check** action + post-enqueue "started" banner (SPEC-124). |
| `StartQualityCheckDialog` | `StartQualityCheckDialog.tsx` | The dashboard's entry point into a check: space `<select>` (from `usableSpaceTargets`) over a keyed `DestinationPicker` in `selectableFiles` mode, a live head-truncated target line, and a confirm that names the target ("Check this folder"/"Check this file"). Enqueues through `useDataQualityCheck` — never a second enqueue path (SPEC-124). |
| `csvReport()`, `parquetReport()` | `reportFixtures.ts` | Report fixtures whose shapes **and wording** are copied from `dqcommon/report.py`, so the "approximate is always qualified" assertions test against real text rather than invented text (SPEC-113). |
