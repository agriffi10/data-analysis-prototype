# Shared-spaces feature (`apps/portal/src/features/shared-spaces/`)

Part of the component inventory (`INDEX.md`, beside this file, is the router).
Public surface only — the code is the source of truth; verify signatures before relying on them.


| Symbol | File | Purpose |
|---|---|---|
| `enqueueSharedSpaceRequest(input)` | `sharedSpaces.service.ts` | One `apiRequest('sharedSpace.enqueue')`, minting the `requestId` and returning it. The constant FIFO group, the schema version and the advisory actor are the API's to stamp — and the caller's `actor` is deliberately NOT sent, because a body carrying one is refused at the door. `ServiceResult<{requestId}>`, never throws. |
| `readSharedConnectionsCache(username)` | `sharedSpaces.service.ts` | Read-only `GetObject` of the per-user cache (`{username}/user_settings/shared-connections.json`); forgiving parse (missing/corrupt → empty, drops malformed entries); `ServiceResult`, never throws. Source for `useConnections` (`features/connections/`, SPEC-052). |
| `useSpaceSuggestions()` | `useSpaceSuggestions.ts` | The signed-in user's own shared spaces as a `SuggestionSource` (`features/user-directory`), for `TableShareDialog`'s space entry. Reads `useConnections` — **no request of its own, no published space directory** — filtered to `kind === 'shared'` + `isConnectionUsable`, over the shared `buildIndex`/`search`. Same three-state `status`, with a failed read and "member of no space" collapsed into `'unavailable'`. Index rebuilt only when the connection list changes (SPEC-158). |
| `ConnectionsPage` | `ConnectionsPage.tsx` | The `/connections` management view: lists shared connections (mono name, role pill, status badge text+icon), Refresh control, empty state, read-error `Banner`, failed-entry reason + Dismiss/Retry; merges cache + local optimistic pending (SPEC-052). |
| `RefreshConnectionsButton` | `RefreshConnectionsButton.tsx` | `IconButton` affordance (SPEC-046 pattern) for `useConnections().refresh`; spins + disables while in-flight (SPEC-052). |
| `useLeaveOrDeleteSharedSpace(username)` | `useLeaveOrDeleteSharedSpace.ts` | `{leave(space), remove(space), busy}` — enqueue `leave` (member self-revoke) / `delete` (owner cascade); no payload; the browser makes no direct AWS call; no-op when signed out (SPEC-054). |
| `LeaveSharedSpaceDialog` | `LeaveSharedSpaceDialog.tsx` | Member's leave confirm (shared danger `ConfirmDialog`); copy notes no data is deleted (SPEC-054). |

| `TransferOwnershipDialog` | `TransferOwnershipDialog.tsx` | Owner's confirm to hand a space to a member (shared `ConfirmDialog`, **no** type-the-name gate — a transfer destroys nothing and the new owner can hand it back). | `useAcknowledgeMembership(username, connections, activeSpaceId)` | `useAcknowledgeMembership.ts` | Effect hook: when a member resolves an `active` shared space they belong to (not owner), enqueues one `acknowledge_membership` per space per browser session (sessionStorage dedup), flipping them Pending → Active in the owner projection. Called from `FilesPage` (SPEC-073). |
| `MembersList` | `MembersList.tsx` | Shared presentational roster: owner tagged + first, others A–Z, per-member Pending/Active chip; optional `onRemove` / `onTransfer` render the per-member owner controls (read-only without them, so the member roster gets none by construction). Used by both member-drawers (SPEC-075/208). |

| `MemberRosterDrawer` | `MemberRosterDrawer.tsx` | Read-only member roster over `MembersList` for non-owner members (Refresh + legacy "not available yet" note); no Add/Remove. Opened by "View members" on an active member card (SPEC-075). |
| `AddMembersDialog` / `parseMemberInput` | `AddMembersDialog.tsx` / `memberInput.ts` | Add-members modal + the parse util (split on comma/space/newline, trim, lowercase, de-dupe, drop tokens failing `CATALOG_IDENTIFIER_RE`) (SPEC-053). **Since SPEC-148 the field is `UsernameChipsField`**: suggestions from the published directory, committed names as chips, the `existing` prop passed through as `exclude` (it includes the owner), invalid tokens SURFACED rather than dropped, and Add gated on at least one chip. | `useCreateSharedConnection(username)` | `useCreateSharedConnection.ts` | `{create(name), busy, pending}` — enqueue a `create` + hold an optimistic LOCAL provisioning entry (no S3 write; the pipeline writes the cache) (SPEC-051). |
