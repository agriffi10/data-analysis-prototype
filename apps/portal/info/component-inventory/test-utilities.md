# Test utilities (`apps/portal/src/test/`)

Part of the component inventory (`INDEX.md`, beside this file, is the router).
Public surface only — the code is the source of truth; verify signatures before relying on them.


| Symbol | File | Purpose |
|---|---|---|
| `expectNoA11yViolations(ui, axeOptions?)` + `ROUTE_AXE_OPTIONS` / `COMPONENT_AXE_OPTIONS` / `WCAG_TAGS` | `test/axe.ts` | Render a node and assert no `axe-core` violations; one centrally-defined WCAG A/AA config (`color-contrast` off — jsdom). Route preset enables landmark/heading/region rules; component preset disables `region`. Co-locate `*.a11y.test.tsx` checks; `npm run test:a11y` runs only those (SPEC-045). `expectContainerHasNoA11yViolations(container, axeOptions?)` checks an ALREADY-RENDERED container, for a state the user must drive into (a dialog opened from a button) — same config (SPEC-124). |
| `mockApi(apiRequest)` → `{answer, fail, calls, routes, bodyFor, queryFor, paramsFor, countOf, fn}` | `test/apiMock.ts` | Programs a mocked `apiRequest` **by route id**, never by call order, and records what each call sent. `paramsFor` reads the PATH parameters: a templated route puts its identifier in the path, so a test reading only the body and the query passes whichever execution id or database the service chose, including the wrong one. |
| `renderWithProviders(ui, {route, path, routes, auth, queryClient, seedFeatureFlags, featureFlags, strictMode})` / `TestProviders` / `createTestQueryClient()` | `test/renderWithProviders.tsx` | The shared harness (react.md §21), on the navigation seam over jsdom's own history. `route` is a path or `{pathname, search?, state?}`, the state held by the seam for the first entry; `path` puts `ui` at a pattern so its params resolve, through Next's `useParams` as a page reads them, and `routes` adds others, both matched by the seam's `matchPath`; the result's `location()` is the seam's location as it stands. `strictMode` renders `StrictMode` as the ROOT — one passed in as `ui` sits under the wrapper and runs every effect once. `featureFlags` seeds a partial set over the all-on defaults (`{archive: false}`) and throws beside `seedFeatureFlags: false`, which would drop it. |
| `renderApp(route, {auth, pages, …})` | `test/appRouter.tsx` | The test App Router: the real `AppChrome` (header, gate, shell) under the harness's providers, around the page Next's stand-in selects from `src/app/**/page.tsx`, or `src/app/not-found.tsx` at an address no page serves. `auth` may be a component providing the context; `pages` adds or replaces a page. The proof of the shell and of every navigation between pages. |
| `traverse(delta)` / `nextPopstate()` / `requests()` / `hold()` / `release()` / `resetStandIn` / `NextStandInRoot` | `test/nextNavigation.ts` | Vitest's `next/navigation` (aliased in `vite.config.ts`), modelling the eight Next behaviours the seam rests on, each with a test. `traverse` goes Back or Forward inside `act`; `requests()` lists the pages Next's router would have fetched; `hold` parks the next router push uncommitted. |
| `selectPage(files, pathname)` / `patternOf(file)` / `matchPage` | `test/pageSelection.ts` | Next's page selection, pure: static before dynamic before catch-all, route groups transparent. Shared by `renderApp` and the record-and-page guard. |
| `readoutPage(name)` / `commits` / `mounts` / `fixture` / `resetReadout` | `test/seamReadout.tsx` | Pages that record the seam's location, type, key, state and params on every commit, for the seam's own scenarios, served as pages through `renderApp`. |
| `wrappersOf(source, page)` | `test/viewSource.ts` | The wrappers an area view puts around its page, read from source, outermost first, for the flag-then-boundary-then-Suspense checks. |
| `installWorkspaceMocks()` / `resetViewport()` / `renderWorkspace(route?, {queryClient?, strictMode?})` / the spies (`mockRunQuery`, `mockGetStatus`, …) / the builders (`ok`, `fail`, `savedFile`, `savedListing`, `succeeded`, `rowsPage`, …) / `seedTabs`, `seedSingle`, `queueRuns` / `statusMap` / `NavRailProbe`, `LocationProbe` / `runScriptSingle`, `runScriptTabs`, `openTableMenu` | `test/queryWorkspaceSupport.tsx` | The shared setup for the query workspace suites (`QueryWorkspace.test.tsx`, `queryWorkspaceDivider.test.tsx`, `queryWorkspaceMobile.test.tsx`): one boundary, one render, one set of fixtures. `renderWorkspace` takes a path or a location with a hand-off's state, and passes `strictMode` through for a hand-off test. A suite that imports it still declares its own `vi.mock` calls for the eight service modules and the editor stub, because mocks are per test file. |
| `withFakeTimers(body)` | `test/fakeTimers.ts` | Runs a test on vitest's fake clock with Testing Library able to drive it: it installs the `jest` stand-in whose `advanceTimersByTime` Testing Library looks for, without which a full-page render hangs on its first `user.click`. Cross a state-updating timer (a poll's ceiling) in an `act` of its own, since React applies the update as that `act` exits (SPEC-234). |
| `SqlEditor` / `monacoLayout` | `test/sqlEditorStub.tsx` | The Monaco stand-in the workspace suites mock `./SqlEditor` with (`vi.mock('./SqlEditor', () => import('../../test/sqlEditorStub'))`): a textarea that drives value/onChange, forwards the selection handle, and exposes each run scope as a button. `monacoLayout` is the shared re-measure spy. |
| `seedRuntimeConfig(partial?)` / `clearRuntimeConfig()` | `test/seedRuntimeConfig.ts` | Puts a spec on the runtime-document path instead of the dev fallback. Most tests need neither — under Vitest `DEV` is true and no load has happened, so `vi.stubEnv`'d `VITE_*` values answer. Seed only when the document itself is the subject, or when a spec stubs `DEV` false (SPEC-192). |
| `readCss()` / `themeBlock(css)` / `darkBlock(css)` / `rootBlock(css)` / `declaredTokens(body)` / `declaredVars(body, prefix)` | `test/cssTokens.ts` | The ONE reader of `src/index.css`, shared by the contrast harness and the Data Explorer's palette tests. Block-scoped by construction: a whole-file `--color-*` match reads the dark block over the light one and every "light" assertion then measures dark-on-dark, passing. Reads the file rather than importing it — Vitest resolves a stylesheet `?raw` to the empty string, which makes such a check pass by finding nothing (SPEC-184, generalised by SPEC-210). |
| `setPrefersDark(next)` / `prefersDarkScheme()` / `resetColorScheme()` | `test/colorScheme.ts` | Drives `(prefers-color-scheme: dark)` for the suite's `matchMedia` stub, and fires `change` as a browser would. Reset before every test by `test-setup.ts` (SPEC-210). |
