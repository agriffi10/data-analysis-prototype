# Data Explorer feature (`apps/portal/src/features/data-explorer/`)

Part of the component inventory (`docs/component-inventory.md` is the router).
Public surface only — the code is the source of truth; verify signatures before relying on them.

Public barrel: `features/data-explorer/index.ts`. Look at a table without writing SQL: a user's
grid gestures are a **description of a query**, and the app renders that description and runs it.

**SPEC-179 mounted the first surfaces** (the `/explore` route, the source picker, the tab strip),
**SPEC-180 replaced its placeholder table with the real grid** (column geometry, a cell cursor with
range selection, the Value panel, and the Record and Text presentations), **SPEC-181 made it
usable** (the per-column menu, filter-by-cell, the expression bar, multi-column ordering, the staged
settings dialog, history and cost) and **SPEC-182 added the two analysis panels** — Calc over the
selection, computed in the browser, and Grouping, which is a real `GROUP BY` — plus the
generated-SQL disclosure. The engine shipped first
(SPEC-178) because it settles the exploration model and the app's only SQL-value interpolation
point.

> Composes `features/catalog/` (the Glue reader, the Athena execution/results layer) and
> `features/saved-queries/` (the `.sql` store, from SPEC-183). It may **not** import
> `features/query/`, and `features/query/` may not import it — enforced by the ESLint layering
> rule (SPEC-176), which this spec is the first to exercise against real files.

### The rule everything else follows

`renderExplorationSql(source, query)` takes the source and the query description **and nothing
else**. Filters, the expression, ordering and grouping render SQL; column visibility, order,
pinning, width, colour and transformers are *presentation* and render nothing, so they cost
nothing and apply instantly. That is structural — a function that cannot reach presentation state
cannot be made to depend on it by a later edit — and `sqlBuilderSweep.test.ts` forbids a second
builder in the feature.

### Model & rendering

| Symbol | File | Purpose |
|---|---|---|
| `renderExplorationSql(source, query)` | `renderExplorationSql.ts` | The ONE SQL builder. `table` → `FROM "db"."tbl"`, `sql` → `FROM (\n<body>\n) AS t` (the newlines are load-bearing — a body ending in a `--` comment would otherwise swallow the closing paren and the alias); filters, expression, ordering and grouping compose identically over either arm. `SELECT *` unless grouping, no trailing semicolon. Throws `ExplorationRenderError` for a description that cannot render — a valueless comparison, a non-numeric numeric value, an invalid or ambiguous grouping, or an ORDER BY Trino would reject. (Trino rejects that last one at ANALYSIS, scanning nothing and billing nothing — what refusing here buys is immediacy, not money: the gesture is refused where the user made it instead of returning an engine error SPEC-106 forbids rendering.) |
| `ExplorationRenderError` | `renderExplorationSql.ts` | The refusal. Its message is **operator text** and names the offending column — SPEC-106 forbids rendering it to a user. |
| `aggregateAlias(aggregate)` | `renderExplorationSql.ts` | The column name an aggregate produces (`COUNT(*)` → `count_all`), and the name an `ORDER BY` may reference. Exported so SPEC-182's panel labels a column with the name the SQL actually emits. |
| `newExploration(source, id?)` / `newExplorationId()` / `emptyExplorationQuery()` / `emptyExplorationPresentation()` / `emptyGrouping()` / `explorationSourceLabel(source)` | `exploration.ts` | The model's constructors — one definition of what "empty" means, so two surfaces cannot disagree about whether `expression` starts `null` or `''`. `emptyGrouping()` is a panel DRAFT: `COUNT(*)` and no columns, which is deliberately **not** grouping mode. |

### Execution & cost

| Symbol | File | Purpose |
|---|---|---|
| `useExploration(exploration \| null)` | `useExploration.ts` | Renders, runs and reports: `{sql, queryExecutionId, state, cost, isPending, error}`. A FAILED/CANCELLED execution is surfaced as an `error` of `{code, message: stateChangeReason}` (SPEC-181) — Athena's refusal is not an error anywhere in the plumbing (the poll RESOLVES), and that shape is what `toUserMessage` maps engine text from. **The rendered SQL is the cache key**, so an identical description is a cache hit rather than a second bill and toggling a sort back costs nothing. Paging is NOT here — the caller pages the execution id through SPEC-176's `useQueryResults`, whose `NextToken` walk scans no extra bytes. A FAILED/CANCELLED execution is evicted **on the way out** (statement change or unmount), never on observing the failure: evicting while mounted refetches immediately, an unbounded loop against StartQueryExecution (AWS does not bill a FAILED query, but this branch also covers CANCELLED, which IS billed for what it scanned). `gcTime: Infinity` is as load-bearing as `staleTime` — under the 5-minute default the cache promise silently expires and the return trip becomes a second execution. |
| `explorerKeys` | `explorerKeys.ts` | Key factory (`all` / `execution(sql)`), rooted at `['data-explorer']` — never hand-build keys. |

### Tab state

| Symbol | File | Purpose |
|---|---|---|
| `useExplorationTabs(username)` | `useExplorationTabs.ts` | Ordered tabs, one active, `sessionStorage` persistence per user, `updateTab(id, fn)` (a description and the history entry it pushes must be written in ONE update), and `openTab` returning **null** at `EXPLORATION_TABS_MAX` so the caller can raise the cap dialog (SPEC-179 renders it). Starts with **no tabs**, unlike `useQueryTabs`' seeded "Query 1" — an exploration needs a source and there is none to guess. `activeTabId` always references an existing tab, or `''` for the legal empty state. |
| `readExplorationTabsState` / `writeExplorationTabsState` / `initialExplorationTabsState` **(internal — not on the barrel)** | `explorationTabs.ts` | The degrade-safe persistence behind it; a corrupt, old or foreign document is discarded **whole**, never partially applied — a half-restored exploration renders SQL from a description the user never built. Validation goes past shape to the fields the renderer BRANCHES on (filter operators, `valueKind`, sort direction, aggregate functions, and that every ledger value is a finite number), because "restorable" is not "renderable": an unknown operator renders `"a" undefined 'x'` and reaches StartQueryExecution. |
| `tabBytesScanned(tab)` | `explorationTabs.ts` | A tab's cumulative bytes, summed from a ledger keyed by **execution id**. That keying is what makes "a cache hit adds nothing" true by construction: a running total would have to *detect* a hit, and a detector can be wrong in the direction that overcharges. |

### The grid (SPEC-180)

| Symbol | File | Purpose |
|---|---|---|
| `ExplorationGrid` / `ExplorationGridHeader` | `ExplorationGrid.tsx`, `ExplorationGridHeader.tsx` | `role="grid"` over the current page: a sticky pinned block, row numbers, a drag grip and a `ColumnResizeHandle` per header. A cell is addressed by (row on the page, column NAME) and reads `row[column.index]`, so display order is free to differ from the execution's. Cells carry an explicit `role="gridcell"` — several accessibility APIs resolve a bare `td` as `cell`, a role with no selected state. |
| `useColumnGeometry(columns, presentation, onChange)` | `useColumnGeometry.ts` | Resolves the tab's presentation against the columns the result actually has → `visible`/`all` plus `setWidth`/`resetWidth`/`toggleHidden`/`togglePinned`/`move`/`moveTo` and the two refusal readers. **Keyed by column NAME**, which is what makes "geometry for a column this result no longer has is discarded" true by construction. Reuses `features/catalog/`'s sizing constants, NOT `useColumnWidths` (index-keyed, per-execution, in-memory). |
| `useCellSelection(rowCount, columns, resetKey)` | `useCellSelection.ts` | The cursor and selection: `ranges` is a list of inclusive rectangles and **the last one is live** (its `from` is the Shift anchor, its `to` the cursor). Pointer, keyboard, whole column, whole row, Ctrl/Cmd+A over the LOADED page, and the WAI-ARIA Space bindings (Ctrl/Cmd+Space = column, Shift+Space = row) so the header and row-number clicks have a keyboard path. Focus follows the cursor by looking the `data-cursor` cell up in the committed DOM — a per-cell ref detaches and attaches in an order React does not promise, and the first keyboard move read a nulled one. Keys arriving from anything but a gridcell are ignored, so the resize handles inside the grid keep their Arrows. `resetKey` changes with the page or the column set and resets during render — an effect would paint one frame of stale coordinates over new rows. The substrate SPEC-182 aggregates over and SPEC-185 copies. |
| `ColumnsPanel` | `ColumnsPanel.tsx` | Hide/show, pin and **Move earlier/later** — the keyboard alternative to dragging a header, announced in a live region. A panel rather than a header menu because SPEC-181 owns the per-column menu. Every refusal rides `Button.disabledReason` (`aria-disabled`, reason in the tab order, never inside the button). |
| `ValuePanel` | `ValuePanel.tsx` | The focused cell's complete value in a read-only `<textarea>` — selectable and copyable, **not focus-trapping**, Escape through the depth-ordered registry. `undefined` (no cell focused) is said in words, never as `NULL`: telling those apart is the panel's job. One tree reflowing: a bottom sheet below `tablet`, a column beside the grid above it. |
| `ExplorationRecordView` / `ExplorationTextView` / `PresentationSwitch` | `*.tsx` | The transposed row (Next/Previous within the page; the default below `tablet`), the fixed-width text rendering of the page, and the Grid/Record/Text control. None of them runs a query. |
| `CellValue` / `cellText(value)` / `NULL_DISPLAY` / `EMPTY_DISPLAY` | `CellValue.tsx`, `cellText.ts` | **NULL and the empty string, told apart** (FR-003 AC5). Athena returns every value as a string; `getQueryResults` now keeps the difference (`null` vs `''`) and this is where it becomes visible, as text rather than as styling. |
| `useSourceColumns(source \| null)` | `useSourceColumns.ts` | The columns a source is known to have before any execution returns: Glue's, for a `table` source (through `features/catalog/`'s cached schema); **empty for `sql`**, whose columns arrive only with `ResultSetMetadata`. The execution's own metadata always wins once it lands — a grouping change replaces the column set wholesale. |

### Filtering, ordering and cost (SPEC-181)

| Symbol | File | Purpose |
|---|---|---|
| `useExplorationQuery(tabs, tabId)` | `useExplorationQuery.ts` | **The one door** a description changes through: `{query, apply, clearAll, clearAllRefusal, canGoBack/Forward, back, forward, suspended, retry, noteFailure}`. One `apply` per gesture is what makes "one gesture is one execution" a property of the feature rather than a rule four surfaces keep. An apply that changes nothing pushes no history (compared with `sameQuery`, not field by field). Takes the **tabs result** rather than reading its own — a second `useExplorationTabs` would be a second writer to one `sessionStorage` key. `suspended` holds back a history step onto a statement already seen to fail (FR-006 AC4): SPEC-178 evicts a failed execution, so restoring its description would start a fresh one. |
| `setFilter` / `clearFilter` / `filterOf` / `setSort` / `clearSort` / `sortOf` / `moveSortPriority` / `moveSortRefusal` / `sameQuery` / `isEmptyQuery` / `operatorTakesValue` / `FILTER_OPERATORS` / `FILTER_OPERATOR_LABELS` | `explorationQueryOps.ts` | The pure edits behind every surface — total, non-mutating, one definition each. **One filter per column** (`setFilter` replaces), sort priorities re-stamped **contiguous** on every edit, and a direction flip keeps its place rather than being promoted. `moveSortPriority` stamps by ARRAY POSITION: re-sorting by the priorities the entries still carry puts them back and the move is a silent no-op. |
| `filterValueKind(type)` | `explorationQueryOps.ts` | The producer for SPEC-178's `valueKind`, from the column's declared type — both Athena's and Glue's spellings, plus `decimal(p,s)`. An unknown type is `'string'`, the safe direction: a quoted value is escaped and a type mismatch is a readable query error. A **boolean** column is `'string'` and will fail at Athena as a type error. |
| `isBareNumeric(value)` | `renderExplorationSql.ts` | The renderer's own numeric gate, **exported** so the two value inputs refuse exactly what it refuses — its own refusal is an `ExplorationRenderError` naming a column and an operator (SPEC-106). Also drives the `disabledReason` on *Filter by this value*. |
| `ColumnFilterMenu` / `ColumnQueryActions` | `ColumnFilterMenu.tsx` | The per-column header menu on the `Menu` primitive: sort asc/desc/clear, six comparisons, the two null tests, clear filter. Its accessible name identifies the column **and its state** (`Column options: note, sorted ascending, sort 1, filtered`) — the header cell's own `aria-label` suppresses everything inside it, so that is the only place a screen reader can hear it. `ColumnQueryActions` is the one object the grid, the header and the cell action share. |
| `FilterValueDialog` | `FilterValueDialog.tsx` | Asks for a comparison's value; cancelling applies nothing. Refuses a non-number for a numeric column, at the input. |
| `ExpressionBar` | `ExpressionBar.tsx` | A verbatim `WHERE` fragment, applied on Enter or Apply and **never on change** — every apply is a bill. Re-seeded during render when the applied expression changes underneath it (history, Remove all), which is what leaves the offending text in place after a failure. **Not gated on `query`** (SPEC-162: a flag is presentation, never authorization). |
| `OrderFilterDialog` / `OrderFilterSettings` | `OrderFilterDialog.tsx` | Every column's visibility, pinning, sort, priority and criteria in **one staged draft** on `FormDialog` — several changes, one execution; Cancel discards the presentation half too, because both halves are one object. No field submits on Enter: every field here is a criteria row. |
| `FilterHistoryControls` | `FilterHistoryControls.tsx` | Back/Forward, each refusing through `Button.disabledReason`. |
| `CostIndicator` | `CostIndicator.tsx` | What this apply scanned and what the tab has scanned. A cache hit **says so** rather than repeating a figure that is true about the execution and false about the gesture. Not a live region. |

### Calc, grouping and the disclosure (SPEC-182)

| Symbol | File | Purpose |
|---|---|---|
| `calcResults(values, state)` / `selectedCellValues(ranges, columns, rows)` / `calcScopeText(count)` | `calc.ts` | The ten aggregates over a cell SELECTION, in the browser — total, never throwing, never `NaN`, because they are read during a drag. `selectedCellValues` deduplicates coordinates (overlapping ranges are one Ctrl/Cmd+click away) and returns values row-major, which is what makes `mode`'s tie deterministic. Numeric-vs-not is the renderer's own `isBareNumeric`, so the panel and the filter cannot disagree about which cells are numbers. `calcScopeText` is the honesty line — "N selected cells **on this page**" — and none of its words are droppable. |
| `percentageOfTotal(values)` / `percentageColumnName(alias)` | `calc.ts` | The grouped result's share column, computed client-side from rows already fetched and **named for the page it describes** (`% of count_all (this page)`) — only one page is in the browser, so any other wording would be read as a share of the table. A zero total yields no shares rather than `Infinity`. |
| `CalcPanel` | `CalcPanel.tsx` | The panel: results, per-function checkboxes, Reset, and the numbers/strings toggle. A side `<aside>` rather than a `Drawer` — a focus trap would put the grid out of reach of a panel that recomputes on every selection change. Nothing in it issues an execution, asserted by count. |
| `GroupingPanel` | `GroupingPanel.tsx` | Grouping columns (dragged from a header or picked, reordered with Move earlier/later) and aggregates from a **closed list**, staged in one draft and applied as ONE execution. Also non-trapping, because the header drag has to land on it. Refuses a duplicate aggregate alias and a grouping the current ordering could not survive, both through the renderer's own rules. |
| `GeneratedSqlDisclosure` | `GeneratedSqlDisclosure.tsx` | The statement the execution used, from `useExploration.sql` — **never re-derived for display**, so the two cannot drift. Available grouped or not; a read-only textarea, so selectable and copyable without a copy control (SPEC-185's). |
| `setGrouping(query, grouping)` / `groupingApplyRefusal(query, grouping)` | `explorationQueryOps.ts` | Grouping mode is exactly "at least one grouping column"; leaving it **drops sorts on aggregate aliases**, which exist only while the grouping does (carried over, `ORDER BY "count_all"` on the raw table is a query Athena rejects, and it misses the cached ungrouped execution). The refusal names the offending sort, because clearing it is the only way out. |
| `groupingNameCollision(grouping)` | `renderExplorationSql.ts` | The output name a grouping would produce **twice**, seeded with the grouping COLUMNS as well as the aggregate aliases — they are projected side by side, so grouping by a column called `count_all` beside `COUNT(*)` yields two result columns of one name, one geometry key and an ordering rule that cannot say which it means. Exported so the panel refuses at the gesture. |
| `ColumnQueryActions.queryRefusalOf(column)` / `CALCULATED_COLUMN_REFUSAL` | `ColumnFilterMenu.tsx`, `ExplorationResultsRegion.tsx` | Why a column takes no filter and no sort. Today it names the appended percentage column — the app's first column that is **not in the query**: the grid draws it like any other, so sorting it is a description the renderer REFUSES (the whole exploration behind an error banner) and filtering it is a `COLUMN_NOT_FOUND`. Asked by the header menu, the settings dialog (the only sort/filter path below `tablet`) and *Filter by this value*; Show, Pin, width and order stay available, because geometry applies to it like any other column. |
| `SaveExplorationDialog` | `SaveExplorationDialog.tsx` | The save flow for an exploration (SPEC-183): a thin host over `features/saved-queries/`'s `SaveQueryDialog` and its Replace confirm, so every SPEC-175 rule about names, destinations, collisions and in-place replacement stays in `useSaveQuery`. What it writes is `useExploration.sql` — the string the execution was handed, never a second rendering. **Mounting IS the open state**: the workspace mounts it on the gesture and unmounts it when done, so reading the hook's own `open` flag would give one dialog two sources of truth. The `Save as query` control it belongs to follows the **`query`** flag, not `dataExplorer` — the mirror of *Explore data* on the Query rail. |
| `useExplorationTabs().setTabSavedQuery(tabId, link)` / `ExplorationTab.savedQuery` | `useExplorationTabs.ts`, `explorationTabs.ts` | The `.sql` file a tab was last saved to, and the only thing that makes `isLinkedSavedQuery` ever true in this feature. By **id**, not "the active tab": the write is async, and linking the wrong tab would make its next re-save replace a file it has nothing to do with. Restored defensively — all four fields or none, so a pre-SPEC-183 document restores the tab without a link rather than being discarded. A save does **not** rename the tab; the label names the source being explored. |
| `groupingOrderingViolation(ordering, grouping)` | `renderExplorationSql.ts` | The ONE ordering rule, returning the offending COLUMN rather than a message: the renderer wraps it in operator text SPEC-106 forbids rendering, the panel wraps it in a sentence a user may read. The `isBareNumeric` precedent — a second rule at the panel is a rule that can disagree, and it would disagree by accepting a grouping the renderer throws on. |
