# User-directory feature (`apps/portal/src/features/user-directory/`)

Part of the component inventory (`docs/component-inventory.md` is the router).
Public surface only — the code is the source of truth; verify signatures before relying on them.

> **The directory is ADVISORY.** It is up to a day stale, it misses users not yet provisioned, and it
> is never an authorization input — the control plane is the authority and already reports an unknown
> name by notification. Nothing here may be used to refuse a name (SPEC-147 FR-005).

| Symbol | File | Purpose |
|---|---|---|
| `getUserDirectory()` | `userDirectory.service.ts` | Reads `_directory/usernames.json` from `userSpaceBucket()` through the shared `readJsonDocument` (SPEC-155 FR-001). FORGIVING: missing, corrupt, unsupported `version` and non-array `usernames` all return an EMPTY success — an unavailable suggestion list means no suggestions, never an error banner. Re-checks every entry against `CATALOG_IDENTIFIER_RE` (the array is rendered into the DOM and used for keys). `ServiceResult<UserDirectory>`, never throws (SPEC-147). |
| `useUserDirectory()` | `useUserDirectory.ts` | `{status, search, generatedAt}`. `search` is a STABLE CALLBACK, not the index — it builds on first call and memoises, so no consumer holds a half-built structure. `staleTime` 1h, `retry: false`, gated on a signed-in user. `status` is `'loading' \| 'ready' \| 'unavailable'`, with errored and empty COLLAPSED into `'unavailable'` so no consumer has to handle both. Returns `[]` unless ready (SPEC-147). |
| `buildIndex(usernames)` / `search(index, query, limit?)` | `usernameTrie.ts` | Pure. One walk builds a character trie (prefix band) plus the flat ordered array the substring band scans. Ranking: exact, then prefix asc, then substring asc; each name once, in its strongest band. The PREFIX band walks and stops early; the SUBSTRING band is a linear scan, short-circuited at `limit` and skipped when the prefix band filled it. Capped at `MAX_INDEXED_USERNAMES` (20,000) with `truncated` set (SPEC-147). |
| `searchWithCost(index, query, limit?)` | `usernameTrie.ts` | `search` + `{nodesVisited, namesScanned}`. Exists so the cost claims are pinned with numbers rather than comments — used by the trie's own tests and nothing else (SPEC-147). |
| `useUsernameSuggestions()` | `useUsernameSuggestions.ts` | The directory as a `SuggestionSource` — `{status, search}` from `useUserDirectory`, stable identity. Thin by design: it exists so SPEC-158's prop lift stayed behaviour-neutral for the two consumers already suggesting usernames. `useUserDirectory` remains the public hook (it also reports `generatedAt`). |
| `UserDirectory`, `UserDirectoryStatus`, `UsernameSearchResult`, `UsernameIndex`, `UserDirectoryDocument`, `SuggestionSource` | `userDirectory.types.ts` | The document shape SPEC-146's builder publishes, what the service returns, and what consumers branch on (SPEC-147). `SuggestionSource` = `{status, search}` — what a suggestion field needs from whatever is suggesting, named for the ROLE because SPEC-158 gave the combobox a second source (the user's own shared spaces). |
| `userDirectoryKeys` | `userDirectoryKeys.ts` | TanStack key factory. ONE key, no arguments — the document is bucket-wide, so nothing about the session changes what is fetched (SPEC-147). |
| `UsernameCombobox` | `UsernameCombobox.tsx` | Accessible single-value typeahead over catalog-safe identifiers. **The suggestion source is a required PROP** (`status` + `search`, i.e. a `SuggestionSource`) since SPEC-158 — it calls no hook of its own, so a caller feeds it the username directory or their own shared spaces. `unlistedNote` overrides the note wording for a name the source does not hold (default: the directory sentence). The full ARIA combobox pattern — NOT built on `Menu` (`role="menu"` + roving focus is wrong here); DOM focus never leaves the input and a virtual cursor moves with `aria-activedescendant`. Enter commits the highlight or splits the typed text through `parseMemberInputDetailed` (`onCommitMany`); a pasted LIST commits immediately, a pasted single name does not. `exclude` refuses with a reason, `suppress` only hides. NEVER blocks a valid unlisted name — it notes it, and only when `status === 'ready'`. Escape closes the list without reaching the enclosing Modal/Drawer. The list is bounded by a MEASUREMENT against its nearest scrollable ancestor — the dialog panel, not the viewport — and the active option is scrolled into the VISIBLE region (SPEC-186 FR-003). |
| `listPlacement({fieldTop, fieldBottom, clipTop, clipBottom})` | `comboboxPlacement.ts` | Pure: which side the suggestion list renders on and how tall it may be. Separate from the component because the property that matters is numeric (the list's far edge must stay inside the clipping box) and jsdom reports every rect as zero (SPEC-186 FR-003). |
| `UsernameChipsField` | `UsernameChipsField.tsx` | Multi-value composition around `UsernameCombobox`, passing the caller's `SuggestionSource` straight through (SPEC-158 — it adds chips, not a data source): committed names as removable chips in a labelled `<ul>`, `chipRemoveLabel` for caller wording, Backspace-on-empty removes the last chip. `renderChips={false}` hands rendering back so a caller can keep ONE combined list (`TableShareDialog`'s user + space chips). Duplicates are a silent no-op; owns no submission logic — reports `string[]` (SPEC-147). |
