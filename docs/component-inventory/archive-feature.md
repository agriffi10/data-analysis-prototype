# Archive feature (`apps/portal/src/features/archive/`)

Part of the component inventory (`docs/component-inventory.md` is the router).
Public surface only — the code is the source of truth; verify signatures before relying on them.

SPEC-172 shipped the whole area at once: both enqueue surfaces, both entry points, both dialogs.
The outcome notifications are produced in Python (`lambdas/archive-notify/`) and are not part of
this surface. The `archive/` folder's read-only behaviour is a FILE-BROWSER concern and lives in
`component-inventory/file-browser-feature.md` (`isWriteLockedPrefix`), not here.

**This feature imports nothing from another feature** (SPEC-172 FR-005 AC5), which is why its
dialogs carry their own name/path helpers rather than reaching into `features/file-browser`.

| Symbol | File | Purpose |
|---|---|---|
| `enqueueArchive(req)` | `archive.service.ts` | Builds the SPEC-168 archive envelope (`requestId` + `mode: 'archive'` + `actor` **raw ID token, top level** + `source.{space,items}`) and FIFO-sends to `VITE_ARCHIVE_QUEUE_URL`. `MessageGroupId` = SHA-256 of `"{spaceBucket}/{space}/"`, so two archives out of one space serialize; `MessageDeduplicationId` = `requestId`, which is **also the archive's permanent identity**. Refuses over-cap selections locally (200 items / 96 KiB serialised, mirroring `arcommon.config` — a Python test reads these two numbers back out of this file) with code `SelectionTooLarge`. `ServiceResult<void>` (enqueued ≠ archived), never throws. |
| `enqueueRestore(req)` | `archive.service.ts` | The SPEC-170 restore envelope (`space` + `archiveId` in place of `source`; the field sets are per-mode and unknown fields are REJECTED, so a superset would be refused). `MessageGroupId` = SHA-256 of the **archive root**, `"{kind}/{name}/archive/{archiveId}/"`, so two restores of ONE archive serialize. **Deliberately not `{archiveBucket}/{archiveRoot}` as SPEC-170 FR-001 wrote it** — the browser does not know that bucket's name and a test enforces the absence; see the delivery doc. |
| `useArchive(space, notify)` | `useArchive.ts` | Dialog + enqueue state for Archive. `open(items)` / `close()` / `submit()` → **`Promise<boolean>`**: the caller clears the selection and invalidates the listing from the RETURN VALUE, because `error` read from the enclosing closure is the value from before the submit. Mints the `requestId` **per submit**. Never wedges: `busy` clears in `finally`, a throw becomes a user-safe error, and a second click in the same tick is dropped by a ref rather than by `busy`. |
| `useRestoreArchive(space, notify)` | `useArchive.ts` | The same for Restore: `openDialog()` / `close()` / `submit(archiveId)` → `Promise<boolean>`. Lowercases and trims the pasted id (S3 keys are case-sensitive, so one archive must have one prefix). The run id and the archive id are always different values. |
| `isArchiveId(value)` | `useArchive.ts` | The client-side UUID-v4 rule, held to the SAME pattern `arcommon.paths` uses. The server is the boundary; this exists so a typo costs a sentence now rather than a notification hours later. |
| `ArchiveButton({onClick, disabledReason?, disabled?, placement?, label})` | `ArchiveButton.tsx` | The entry point, in the two homes a per-item action has in this file browser: `placement: 'toolbar'` (icon + a label from tablet up, like Copy/Move/Delete) and `'panel'` (full width, in both details panels). `disabledReason` renders through `Button`'s `aria-disabled` path, so the refusal stays focusable. `label` is the ACCESSIBLE NAME and is queried by the `GATED_SURFACES` walking test. |
| `ArchiveDialog({items, rootPrefix, busy, submitError, onConfirm, onCancel})` | `ArchiveDialog.tsx` | The confirm (SPEC-172 FR-002), on `ConfirmDialog` **because** `FormDialog` has the Enter-to-submit affordance this dialog must not have. Focus lands on Cancel, Enter cancels, `busy` locks dismissal, and it names the consequence twice: the data leaves this space, and a restore takes hours. It deliberately does **not** render "This can't be undone" — a restore is exactly that. |
| `RestoreArchiveButton({onClick, fullWidth?})` | `RestoreArchiveButton.tsx` | The primary-toolbar control. `fullWidth` for the mobile action bar, which is mount-gated rather than CSS-hidden (SPEC-099 FR-005). |
| `RestoreArchiveDialog({spaceLabel, busy?, submitError?, onSubmit, onCancel})` | `RestoreArchiveDialog.tsx` | The pasted-id modal. One field, so Enter submits from it — the opposite call from `ArchiveDialog`, for the opposite reason. Validates **on submit** and never through `submitDisabled`, because a disabled control is not a refusal and the user needs to be told what a valid id looks like. Names the space the restore lands in (it comes from the route, SPEC-113's rule). |
| `ARCHIVE_RESERVED_ROOTS`, `archiveRefusal(items, rootPrefix)` | `archiveSelection.ts` | The portal-managed roots that may never be an archive source, mirroring `arcommon.config.RESERVED_SOURCE_ROOTS` — **set equality is asserted by a test**, because a divergence shows up as a request the browser sends and the plane refuses. `archiveRefusal` reproduces all THREE ways one is selected: the folder, anything beneath it, and an ANCESTOR that contains it (selecting the space root). Anchored at the space root, so a user's own `alice/backups/archive/` is archivable. |
| `ArchiveRequest`, `RestoreRequest`, `ArchiveItem`, `ArchiveSpace` | `src/types/archive.types.ts` | The request shapes matching the SPEC-168/170 contracts. A folder's `key` carries its trailing slash — the plane expands a folder by LISTING that prefix. |
