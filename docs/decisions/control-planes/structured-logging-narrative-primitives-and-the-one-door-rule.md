description: "**Structured logging** goes through `cpcommon.observability` only — and \"only\" includes the library's **private names**, which no module outside it and the two named test harnesses may reach: one such reach survived as a silent no-op after the name behind it was deleted upstream. **No `@traced`/`@step` function may be a generator** — the library refuses one at decoration, so it is a cold start that never completes rather than a bad span. The logs queue is FIFO with **one message group per EVENT** — a FIFO group gives up ten messages until they are deleted, so the group is the sweep's ceiling, and one per service saturated under a single session — swept on a schedule, appended under ETag CAS, retained forever. `@traced` outermost — **except the API**, where one decorator sits outside it to turn an unpredicted fault into a declared code: a catch INSIDE the span ends every failed request successfully and the fault is recorded nowhere. Messages are literals. The **`error.stack` exemption covers file contents, NOT credentials**, and it covers **no field a call site chooses to emit** — neither a **SQL statement** nor an Athena **`stateChangeReason`** may be one: both quote a user's cell values back; `sql_bytes` and `state` instead. The API **prevents rather than redacts**: there is no scrubber, a handler is never given a credential, and an AST sweep is what holds it."

The pipe SPEC-127/128/129 built carries **boundaries only** (the [pipe entry](structured-logging-pipe.md)), and SPEC-130 opens the door to the narrative half. `cpcommon.observability` gains `info`/`warning`/`error` and `step(name)` — the module's full surface is `init`/`flush`/`traced`/`step`/`stamp`/`info`/`warning`/`error`, plus `run_traceparent` since SPEC-225 — and **no VERB imports `log_foundry`** — two test harnesses do, deliberately, since a harness that swaps the process sink must call `configure` (SPEC-224 scoped this; the absolute was never true): an emitter sits in the middle of business logic where an exception is a real failure path, so the never-raise discipline needs one door rather than thirty-four. `step` is a **thin** alias for `lf.trace` and must stay one: the library decorator is non-swallowing, and `@traced` sits **outermost above `@notifies_on_failure`**, so a step that caught anything would cost the user their failure notification. Messages are **literals**, everything variable is a field (an f-string message mints a distinct string per run and can be neither counted nor filtered). The narrative **never reaches the console**: `echo=` is prohibited repo-wide, and since SPEC-224 the prohibition is a mapping `_emit` reads rather than a grep, dropped-and-warned when passed as a field — **and it is not a silent no-op**, which this entry claimed until SPEC-224 measured it: left in place `echo` collides with the keyword `_emit` always passes and raises `TypeError` into business logic, where `fields` (reserved by the library since 1.0.0, and dropped alongside it) raises nothing and is silently reinterpreted. Both drops are asserted, warning included; the one named exposure is `init`'s `StdoutSink` fallback when `LOGS_QUEUE_URL` is unset, which **stays** because it is the cold-start safety property the module is shaped around (PR #196) and is bounded by the `logging.getLogger()` calls already putting the same keys in the same log group.

Two identity defects fixed at the same time, because instrumenting on top of them would have multiplied the damage: `traced` now passes **`name=verb`** (without it `log-foundry` falls back to `fn.__qualname__` and every root span in the fleet read `function: "handler"`) — a **discontinuity in a store retained forever, accepted without migration** since rewriting appended NDJSON would risk a day of logs to save a `WHERE` clause, with `fields.verb` populated on both sides so a query spans the cutover; and **`verb` moved from a span default to baggage** (set after `_reset_context`, which clears the whole mapping), because a span default reaches that span's own events and nothing nested — the first `step` child would have carried `request_id` but not the verb that produced it. Consumers: SPEC-131 (sweep), 132 (data-quality), 133 (DLQ drain), 134→137 (the rest of the fleet).

**SPEC-131 added an eighth name, `stamp(**fields)`** (trace baggage), because the sweep needed an invocation-scoped join key on the boundary spans and the only alternative was importing `log_foundry` at a call site — the one-door rule survives by widening the door, not by excepting it; `_stamp_verb` and `_stamp_request_id` now delegate to it. **SPEC-131's own bound is structural:** the sweep emits into the queue it drains, so its event count is O(1) in messages **and in waves**, and O(D) in the destinations it touched — a per-message emitter would give that queue a floor it could never get below, and a per-wave one makes its own volume grow with the waves a busy queue forces on it. The wave loop broke it (three events plus four per day-group every wave, defended as a ratio below one; 12,772 of the queue's 42,714 sends on the afternoon of 2026-09-10, about 640 a sweep, while it was still grouped by service) until no emitter was left inside the loop: each destination is tallied across the waves and emitted once, a sweep is **one event per destination plus three**, plus at most one per condition it reports once per sweep and a few per destination that degraded, and an empty one two; the guard is `test_a_sweep_emits_the_same_events_however_many_waves_it_takes`, which demands that no emitter is called between the sweep's first receive and its last, and the same events from two waves and from six, and proves it drove every line of the sweep bar the handler's once-per-sweep exits — so a branch added to the sweep fails it until the guard drives that branch too. A check on where an emitter is *written* was tried first and evaded five ordinary ways; a guard over spellings guards a spelling. Detail: `lambdas/info/planes/standalone.md`. Its CloudWatch calls **stay alongside** the events, uniquely for that function: the sink is SQS-only, so a sweep that cannot write to S3 cannot report through the structured store that it could not write to S3. Detail: `spec-delivery/SPEC-130`, `spec-delivery/SPEC-131`.

**`@traced` goes outermost except in the API**, where one decorator sits outside it to turn an unpredicted fault into a declared code: a catch inside the span ends every failed request successfully and the fault is recorded nowhere.

**The API prevents rather than redacts**: there is no scrubber, a handler is never given a credential, and an AST sweep is what holds it.
